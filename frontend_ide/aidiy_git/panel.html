はじめての Git

変更を確かめて、履歴に残す

Git は、ファイルの変更を記録する仕組みです。まずは自分の PC に履歴を残しましょう。GitHub への送信は後からでもできます。

最初のコミットまで

  1. 差分を見る

    「Git」タブの「未ステージ」でファイル名をクリックすると、何が変わったか見られます。自分が変更したファイルから確認します。

  2. 残したい変更を選ぶ

    ファイルの横の「＋」で「ステージ済」に移します。ステージとは、次に記録する変更を選ぶことです。「−」で選び直せます。ファイルは消えません。

  3. ひとこと書いてコミット

    「README に起動手順を追加」のように変更内容を書き、「コミット」を押します。「履歴」で確認できます。この時点では、まだ他の人には送られていません。

サーバーと共有するとき

取得
サーバーの最新の履歴を確認します。作業中のファイルは変わりません。
取り込み
サーバー側の変更を作業中のブランチに反映します。このパネルでは履歴が分岐していると停止します。
送信
コミットをサーバーに共有します。確認画面で送信先とブランチ名を確認してください。

迷ったら「強制送信」は押さない。 サーバーの履歴を上書きする操作です。取り込みが止まったら、先に変更の状況を確認してください。

「リポジトリ」は Git で管理する作業場所、「ブランチ」は作業の流れ、「リモート」は共有先です。リポジトリが複数ある場合は、操作する対象を先に選びます。GitHub が共有先の場合だけ PR・Issue タブが表示されます。
