# 初期ウィンドウ配置の変更・確認

## 変更先と座標

Diagから起動するCPUは、Diagパネルがある画面の作業領域を基準に、右端を8 DIP、下端を206 DIP空けた定位置へ表示します。Diagを同じ画面内で移動しても追従せず、マウスポインターを別画面へ移しても起動先は変わりません。下端余白はDiagミニの固定高さ190 DIPと従来の8 DIPずつの余白に合わせていますが、現在のDiagパネル位置の上へ置く処理ではありません。小画面では作業領域に収めます。

画面選択はCPU起動時だけDiagの親子IPCで現在の作業領域を読み、環境変数 `AIDIY_DEVELOPMENT_DISPLAY_AREA` で受け渡します。rendererやHTTP APIに座標指定は公開せず、読取失敗時はCPU起動を止めて再試行を案内します。Diag指定なしの単独CPUは従来どおり主画面、IDE子CPUは親IDE、VRは選択した画面を優先します。`checks/cpu-chart.test.mjs` は固定位置とミニ寸法の整合、`checks/window-layout.test.mjs` は画面選択・マウス位置との分離・手動移動後の再フォーカスを確認します。

初期サイズ・座標は `frontend_ide/デスクトップ/window-layout.cjs` の `windowBounds()`、最小サイズは `windowMinimumSize()` に集約します。`desktop.cjs` の `createWindow()` が生成時だけ適用します。単独起動はマウスポインター側、IDE連携は親IDEがあるディスプレイの `workArea` を使います。座標はタスクバー等を除く論理座標で、負の座標を持つサブ画面も扱います。

Codeは左上、Liveは右上へ、作業領域の端から8px空けて表示します。IDE連携でも親窓の内側へ寄せず、同じ画面の隅を基準にします。通常の幅480・高さ600と、小画面に収める上限は維持します。

Naviは単独起動・IDEからの起動とも対象画面の作業領域の左中央に、左端から8px空けて配置します。通常サイズはCodeと同じ480×600、最小サイズは360×480です（小画面では作業領域に収めます）。VR中の新規窓も操作した画面を基準とします。IDE内の一時描画は別窓の準備完了まで不可視にし、準備失敗時は本体にエラーを表示します。

IDE連携Codeの2枚目以降だけ、タイトルと共通の `record.slot` に従って右下へ24px単位でずらします。先頭は0px、後続は24〜120pxを循環し、画面内へ制限します。7枚目以降も先頭の0pxへ戻しません。閉じたslotは再利用されます。小画面で余白がない方向はずらさず、窓を画面外へ追い出さないことを優先します。単独CodeとLiveにはこのずらしを適用しません。ピン留めビューアは従来の親IDE基準の配置を維持します。

Consoleの高さは横長（作業領域の幅 > 高さ）で1/3、縦長・正方形で1/4を四捨五入します。幅2/3で左下に端から8px空けて配置し、複数窓は28pxずつ右上へずらします。CLI指定のConsoleも左下に配置し、既存の800×600サイズは維持します（小画面では作業領域内へ縮小）。最小高さ180は初期高さ以下に抑えるため、低い画面でも比率を上書きしません。

現行実装には終了時の座標保存・次回起動時の復元はありません。開いている通常窓の手動移動・リサイズは再フォーカスでは変更せず、新しく生成した窓だけ初期配置を使います。画面回転・ディスプレイ変更でも通常窓を勝手に再配置しません。例外は、利用者が明示的に選択する次のVR表示です。

## IDEの全ディスプレイ表示（VR）

画面上の名称はVRです（内部の `allDisplays` / `全画面横断.cjs` は維持）。利用開始済みのElectron版3D画面から入り、全ディスプレイにまたがる窓へ切り替えます。現在はExplorer・軌跡だけを自動で別窓へ移し、閲覧・比較はIDE内に保持します。各ディスプレイ右上の操作欄またはF11で解除し、Explorer・軌跡の別窓を閉じます。手動で外出ししたViewer等は保持します。

VR中の起動位置、画面構成変更、DPIと復帰寸法、中心の長押し移動、検証条件は [Vue共通画面変更手順のVR節](./frontend_ide,Vue共通画面変更手順.md#vrボタンの表示と切り替え) と同文書の「各モジュールの長押し窓移動」を参照します。同期元は `デスクトップ/全画面横断.cjs`、`App.vue`、`開発スペース.vue`、`ファイル一覧.vue` です。

IDEから開く子窓は最前面ピンONで生成し、VR中だけ解除を禁止します。通常時はOFFにでき、VR終了時にはVR前のユーザー選択へ戻ります。寿命・セッションはmainの `record.owner` で管理し、OFFでも親より手前に残る `BrowserWindow.parent` / `setParentWindow(owner)` は設定しません。IDEフォーカス・ALL切り替え・軌跡リサイズで子窓を強制再固定せず、同じ `floating` 層で選択されたON窓だけを手前にします。単独起動はOFFです。詳細は [最前面ピンの共通方針](./共通,Electronウィンドウ基本方針.md#タイトル操作と最前面ピン) を参照してください。本文の旧「ピン留め窓」はDOMの別ウィンドウ化を指し、画面上では「↗ 別ウィンドウ」として📌の最前面切替と区別します。

## 確認

`node --test frontend_ide/checks/window-layout.test.mjs frontend_ide/checks/code-window-title.test.mjs frontend_ide/checks/navigation-size.test.cjs frontend_ide/checks/panel-windows.test.mjs`

横長・縦長・正方形・小画面・負座標、親IDEを動かした場合、複数Code、slot再利用、単独起動と連携起動の画面選択、手動配置後の再フォーカスを確認します。Electron生成のテストは実 `createWindow()` と模擬OSを使うため、OS実画面・DPI・タスクバー・ウィンドウマネージャーの挙動の確認とは別です。実機では各向きの初期表示を撮影し、Code 1/2/3、閉じて再作成、Live、Consoleの上下端・読みやすさを確認してください。

ALLのロジック・中心補正は `node --test frontend_ide/checks/all-displays.test.mjs frontend_ide/checks/workflow-components.test.mjs` で確認します。4画面・負座標・拡大率混在・最大化からの往復・画面取り外し・IPCの呼び出し元制限を含みます。

実Electron確認は、画面の変更を反映した配布物を用意してから `node frontend_ide/scripts/check-all-displays.mjs` を実行します。一時プロジェクトと専用プロファイルを使い、利用者の画面にテスト窓を出さず、軌跡・エクスプローラーの自動別窓化と比較の本体内保持、VRの実寸・解除・最大化復帰、バーの非表示、復帰ボタンの位置・ホバー・フォーカスを確認します。画面と結果は `temp/all-displays-check/` に保存します。この確認は接続中の実画面構成だけを対象にするため、複数ディスプレイでの見え方はその実機でも確認してください。
