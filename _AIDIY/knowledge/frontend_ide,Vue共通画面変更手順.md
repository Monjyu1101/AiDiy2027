# Vue共通画面変更手順

> 文書: `frontend_ide,Vue共通画面変更手順.md` | 実装: `frontend_ide/src/App.vue`, `frontend_ide/src/components/ファイル閲覧/ファイル一覧.vue`, `frontend_ide/server.mjs`, `frontend_ide/host/src/vscode-html.ts`

## 機能フォルダと共通部品の所有者

`src/App.vue` は画面の組み合わせ、`src/main.js` は起動、`src/style.css` は共通レイアウトを担当します。Console・Code・Live・IDEはいずれも同じ Vue 3 基盤です。Code / Live の VS Code 版も同じ配布画面を読み込みます。

シアン接続バー上の通常タイトル行は `src/components/共通表示/タイトルバー配色.css` のトークン（背景 `#30343a`、主文字・補助文字 `#fff`）を使います。`.panel-brand` の共通ルールにまとめ、単独窓・IDE内のWebパネル・Task / Team・Viewer / Explorer別窓でdesktop条件による色の差を付けません。Diag / Discordも同じトークンを配布へ取り込みます。シアンバー下の通常本文・タブ土台・見出し・空白領域は `#000` に揃え、タイトル用トークンは本文へ転用しません。Task / Teamのログインカード・内側パネル・独立Task窓・表の見出しと空行・編集窓の地色も黒にし、表のデータ行や入力・選択の配色は残します。Consoleのxterm描画面と補完下地も同じ黒へ揃えます。入力・選択・状態色、閲覧するWebページ・画像、2Dページの内容色、接続バーの明滅は維持します。ピン留めボタンは通常・固定・hoverとも背景を透明にし、親のタイトル帯を透かします。固定状態はアイコンと枠で区別し、黒い内側影は付けません。Browserの全画面ガラスだけは透明背景と黒文字の専用トークンで上書きし、通常タイトル行へ揃えないでください。`checks/titlebar-theme.test.mjs` で共有経路と例外を確認します。

通常画面と機能内の補助処理は `src/components/`、独立したダイアログは `src/dialog/` に配置します。基準は [Electron の Avatar 構成例](./共通,Electronウィンドウ基本方針.md#renderer-のフォルダ構成avatar-を実例にする)です。

- `components/コード/`: コードパネル・通信・会話到着演出（Liveも共有）
- `components/ライブ/`: ライブパネル・通信
- `components/コンソール/`: コンソールパネル・コマンド補完・進捗表示・開始表示（Code / Liveも共有）
- `components/開発スペース/`: 開発スペース・宇宙キャンバス・描画・視点・経路記録
- `components/ファイル閲覧/`: 一覧・ビューア・フォルダページ・アイコン・ファイル操作・最新ファイル・走査警告
- `components/ファイル検索/`: AI検索パネル
- `components/下書き連携/`: 受け渡し・連携先登録
- `components/共通表示/`: 状態バー・接続状態・会話表示CSS
- `components/ブラウザ/`: ブラウザパネル・URL表示・起動
- `components/添付ファイル/`: チャット添付・ファイル送信
- `components/タスクチーム/`: 専用 bundle の入口・API・部品・機能内ダイアログと別窓
- `dialog/`: ファイル解析・ファイル履歴・下書き連携の各ダイアログと `共通ダイアログ.vue`

日本語の機能フォルダを維持し、描画・通信だけを `engines` / `transports` などへ分散しません。既存の関数名・props・emit・保存キー・IPC/API・CSSクラスは互換契約として保ち、移動だけで変更しません。`host/src` のDiscord共有モジュール、公開起動入口、worker、配布URLも維持します。

移動時は通常のimportに加え、テストのreadFile・仮想require、型宣言の隣接、`viewer/server.mjs` の最新ファイル共有、`aidiy_console/console.mjs` のPowerShell補完情報を確認してください。日本語パスをファイルAPIへ渡すときはURLオブジェクトか `fileURLToPath()` を使い、URLの `.pathname` を直接ファイル名として使わないでください。`checks/component-paths.mjs` は実Vueマウントの論理名とファイルの対応を一か所にまとめます。

## Task / Team の独立版（Avatarからの移設）

IDEの「TASK」「TEAM」は既存Code / Liveと同じ所有窓・📌・VR・終了管理に入り、Core内部認証で開きます。タイトルは `AiDiy IDE / TASK` / `AiDiy IDE / TEAM`、単独は `AiDiy TASK` / `AiDiy TEAM` です。同じIDEセッションでは種類ごとに既存窓を再利用し、初期化中の要求も集約します。別IDEセッションのプロジェクトを黙って流用しません。単独起動は種類・正規化済みプロジェクト・起動モードをキーに二重起動を防ぎます。

IDE連携のプロジェクトは起動元の実在フォルダに固定します。編集UIの選択・参照を無効化し、Node proxyでも登録・更新先を照合します。既存レコードを別プロジェクトへ付け替える更新も拒否します。各Task窓の認証・選択・終了は同じ起動グループ内だけに通知します。

`frontend_ide/src/components/タスクチーム/` は Avatar から移設した AIタスク・AIチームの独立画面です。Web／Avatar内の旧画面・メニュー・専用通信設定は撤去済みで、実行時に Avatar の配布物やサーバーを読み込みません。Task / Team 専用の `taskteam.js` / `taskteam.css` を生成し、Code / Live の画面 bundle へ Three.js・Mermaid を混ぜません。

- `python frontend_ide/_setup.py` または全体setupのIDE群を選択して準備します。`aidiy_task` / `aidiy_team` で個別Electron起動、`--browser` で同じ画面をWeb起動します。
- ElectronのTaskは元Avatarと同じ要求・フロー図・明細の3独立ウィンドウと編集／応答内容用の別窓を持ちます。起動直後とログアウト後は要求の主画面だけを表示し、ログイン成功後も要求の主画面だけを表示し、フロー図・明細はユーザーが各ボタンで開きます。ログアウトは編集窓も閉じ、主画面を閉じていた場合は先に主画面を再表示します。3画面はそれぞれ閉じられ、各画面右上のボタンで閉じた画面を再表示できます。3画面すべてを閉じると編集窓も閉じ、Taskアプリだけが終了します。Web版は3ペイン一体表示です。
- Taskの認証は同一起動のメインプロセス内メモリで同期し、要求画面を先に閉じても残りの画面を利用できます。他アプリへ共有せず、最終終了時に破棄します。選択タスクと編集完了は同じ起動元の画面間で同期します。
- 実Windowsでの窓寿命の確認は、Core／TaskTeamを起動して `node frontend_ide/scripts/check-task-desktop.mjs` を実行します。ローカル試験用アカウントで認証し、各主画面の個別終了・右上ボタンからの再表示・連打・主画面なしのログアウト・再ログイン・全終了を確認します。業務データは変更しません。アニメーション用の一時窓は主画面数に含めず、起動完了通知を待ちます。
- 3窓の切断・復帰も調べる場合は、環境変数 `AIDIY_TEST_CONNECTION_INTERRUPT=1` を付けて同じ試験を実行します。`TASK_CONNECTION_READY` が出てからDiagでTaskTeamだけを停止し、`TASK_CONNECTION_OFFLINE` の後に再起動します。全3窓の表示が接続済みに戻ってから窓寿命の試験へ進みます。Coreは維持し、試験後は環境変数を解除します。
- 単独起動のログインは既存Coreの利用者認証を使用します。Task / Team とAvatarの認証保存を分け、片方のログアウトで別アプリの保存情報を消しません。バックエンドの業務データは共通です。
- Task / Teamのログインは共通パネルで管理します。上部のAiDiyアイコンは黒背景に置き、Code未入力画面と同じ `welcome-mark` の二重四角形・逆回転を再利用します。入力カードは既存ダイアログに合わせた薄い青紫で、アイコンまでカード色で囲みません。カード内の重複タイトルやサーバー案内は表示しません。低い窓ではスクロールできます。回転はCodeと同じ共通CSSに任せ、Task / Teamだけを停止する上書きは加えません。
- Coreは `PORT_CORE`（既定8091）、Task / Teamは共通の `PORT_TASKTEAM`（既定8093）です。起動元サーバーが配置先設定からloopback宛先を決定し、画面から任意URLや秘密設定を渡せないようにします。
- Codeと共通の状態バーを使いますが、シアン脈動の判定はtoolsではなくTask / Teamの `/health` による実疎通です。停止・通信失敗時は接続済みに見せません。
- 元Avatarのコピー元を更新した際は必要な変更だけを明示的に反映します。コピー版から元ファイルを削除・自動同期しません。

検証は `node --test frontend_ide/checks/taskteam-*.test.mjs frontend_ide/checks/task-team-launchers.test.mjs` と `python -m unittest discover -s scripts/checks -p test_task_team_launchers.py` を使用します。実業務の登録・実行はテストで行わず、模擬APIと一時フォルダで確認します。

## 端末でのビルドが日本語パスで停止する場合

Vite 8.3.4 の Rolldown 進捗表示は、日本語パスを表示幅で切り詰める際に `not a char boundary` で停止することがあります。`scripts/build.mjs` の `ビルド実行()` はビルド中だけ `CI=1` の行単位ログを使い、終了時に元の環境変数へ戻します。通常ログ・警告・エラーは維持し、ソース名や依存パッケージ本体は変更しません。

修正確認は端末付きの `npm run build` と全体 `_setup.py` で行います。パイプへの出力だけでは端末専用の進捗処理を確認できません。Code / Live の VSIX 生成も同じ共通ビルドを通るため、両方の生成成功と setup の終了コードを確認します。

## 変更先の選び方

`viewer/_start.py` を共用する IDE / Console / Task / Team / Browser の起動ログは、配置先リポジトリの `temp/aidiy_<kind>/logs/<UUID>.log` に保存する。閲覧プロジェクトやカレントディレクトリから保存先を決めず、旧 `viewer/out/` のログは移行・削除・退避先利用しない。ElectronのuserData・profile・会話履歴は選択プロジェクトの `_AIDIY/aidiy_<pg>/` に保存する。`python -B -m unittest discover -s frontend_ide/viewer/checks -p test_start.py` で5種類の保存先・別起動のログ分離・旧ログ保持・保存失敗時の非起動を確認する。

Mac のアプリ名とメニューは `desktop.cjs` と `host/scripts/MacOS-Menu.cjs` で扱います。Console / Code / Live / IDE の単独起動・IDE子窓・ピン留め・ブラウザ窓は同じアプリメニューを使います。⌘Q / アプリメニューの「閉じる」は親窓の既存 close を通し、⌘W はフォーカス中の窓だけを閉じます。Mac のシステム Dock「終了」も IDE の利用中確認を通します。親との切断時の回収は `forcedQuit` で確認待ちにしません。編集キーは native role に任せ、Console の選択コピーやシェルへの Ctrl+C を main のキー処理で奪わないでください。`node --test checks/code-window-title.test.mjs host/checks/mac-menu.test.cjs` は各起動種別・終了確認と親子窓の寿命を確認します。

IDEのElectron版はプロジェクト表示行の名前のすぐ右側に並ぶ「Console」「Code」「Live」から別ウィンドウを開き、Web版は画面内タブです。切り分けは `window.aidiyWindow` で行います。IPCにはアプリ種別だけを渡し、プロジェクト・モードはメインプロセスでIDEサーバーの状態から取得します。

Codeの回答通知は、IDEブラウザー版のCodeタブだけ `page-notifications` でページ中央へ表示します。Navi内・別窓・単独・VS CodeのCodeは各自の領域内へ表示します。Naviの別窓化では同じVue DOMを別Documentへ移すため、通知・文字送り・飛行演出・可視状態・タイマーは発言要素の `ownerDocument` とその `defaultView` を使います。元IDEのglobal documentへ追加しないでください。`checks/code-notification-ownership.test.mjs` で複数窓、移動、非表示、破棄、Web例外と領域内の飛行を検証します。

画面は `frontend_ide/src/` の対応する日本語機能フォルダを変更します。Code / LiveをIDEへ配置するときも同じVue部品を使用します。ホストと通信プロトコルは `frontend_ide/host`、ファイルAPIとOffice表示資産は `frontend_ide/viewer` に統合しています。親ディレクトリ数を固定して共通設定やHermesを探さず、配置先から親方向へ探索してください。

IDEのオンライン利用では、`viewer/core-connection.mjs` がConsoleと同じ `PORT_TOOLS`（既定8095）の `GET /aidiy_code_agents/ping` を10秒ごとに確認し、`src/App.vue` も状態を10秒ごとに取得します。応答期限はConsoleと同じ1.5秒で、`status: "ok"` と `name: "aidiy_code_agents"` を確認します。Code / Live子パネルの接続先は `PORT_CORE` のままです。接続済みの定期確認中は `connected=true` / `connecting=false` を維持し、確認が失敗した時に接続表示を変えます。初回接続と切断後の再接続では `connecting=true` を表示します。tools停止でも利用開始時刻・作業・子窓を維持してください。単体検証は `node --test frontend_ide/viewer/checks/connection.test.mjs`、実画面検証はVue配布ファイル生成後の `node frontend_ide/scripts/check-connection.mjs`（Chromeを任意配置している場合は `CHROME_PATH` で指定）。模擬toolsを使い、10秒周期・定期確認中の表示維持・停止と復帰を確認し、日本時間の日時付き画像を `temp/connection-check/` へ保存します。

接続監視の負荷を確認する場合は `node --test frontend_ide/checks/monitoring.test.mjs frontend_ide/viewer/checks/connection.test.mjs` を使います。IDE・ピン留めビューアの状態取得、IDEのtools確認、Consoleのtools確認は10秒周期です。Codeは切断をWebSocketで検知し、再試行だけ10秒待ちます。初回確認・手動操作は即時のままです。Liveは既存のWebSocket通知を使い、定期HTTP確認を追加しません。Code / Liveの20秒ping、Consoleの15秒pingと端末ACK、音声処理の周期は変更しません。子窓の400ms監視とパネル寿命の250ms同期は終了連携用であり、接続疎通の周期と混同しないでください。

非表示のIDEはCanvas描画と毎フレームの配置取得を止め、再表示時は1つの描画ループだけを再開します。Web版のLiveを隠す時は、会話・下書き・接続を保持したまま `AudioCloud.setVisible(false)` で描画を停止し、StatusBarのclock-pulseも止めます。画面全体の非表示とパネルの非表示は別々に扱い、Canvasが0サイズの間も描かず、表示・サイズ復帰でRAFを1本だけ再開します。20秒の接続pingは変更しません。`checks/live-visibility.test.mjs` は実LivePanel・AudioCloud・StatusBarでこの寿命を検証します。接続バーは未接続の黒表示・画面非表示では50msの更新を止め、表示復帰時に現在時刻へ揃えます。Canvasのラベル幅は文字・フォントごとに保持し、階層再構築・サイズ変更・フォント読込時に破棄します。上記テストの呼出し回数は処理削減の確認用で、実機のCPU使用率を測定した値ではありません。画面の見た目・OSごとのCPU/GPU負荷は実画面検証で別途確認してください。

Codeのオフラインモデル候補は `same`（変更なし）を使い、選択時はHermesへ `--model` / `--provider` を付けずに呼び出します。オンラインの `auto`（AI判断）とは区別します。オフラインの選択値は `_AIDIY/aidiy_code/aidiy_code_model_offline.json` に保存します。

エクスプローラーは `ファイル一覧.vue` 一部品にまとめます。入力はtree/root/selected/current/startedAt/open、出力はupdate:open/select/clear/marksです。検索マークはイベントで宇宙へ伝え、エクスプローラーからCanvas内部を書き換えないでください。利用開始時刻が変わると時刻検索を初期化します。

最終更新表示と自動追跡の候補は `src/components/ファイル閲覧/最新ファイル.js` の `latestFiles()` で選び、全階層の `_AIDIY`・`_data`・`_datas` 配下を除外します。`ファイル一覧.vue` の一覧計算と `viewer/server.mjs` の `/api/latest`（約1分周期）の両方で同じ関数を使ってください。`since` は前回の最新更新日時（ミリ秒）で、同じhh:mm:ssの秒頭まで含めて候補を返します。`createLatestUpdates()` は取得済みのパスと更新日時を覚え、前回の最後のファイル等の未変更分を取り除いて判定します。同じ秒の別ファイルを落とさず、同じパス自体がさらに更新された場合も拾います。

最終更新欄は初回に最新の1件を表示します。次回以降は新しい更新だけを古い順に並べ、更新なしなら前回の表示を維持します。3行程度の欄でスクロールでき、各行のクリックは通常の手動選択を使います。フィルター切替では基準を取り直し、切替直後の一覧だけで自動探索を開始しません。ツリー表示・バックアップ・Gitの対象条件へ最終更新の除外を転用しないでください。`node --test frontend_ide/viewer/checks/latest.test.mjs` でフィルターON / OFF、記録更新の無視、複数更新、秒境界の重複除外、同じパスの再更新、候補なしを確認します。

一覧の自動更新は最終更新候補に加え、同じ `/api/latest` 応答の `scan.files` と表示中の走査の件数の差でも判定します。フィルターONではバックアップ対象だけ、OFFでは通常の一覧対象全体を数え、件数専用の走査や表示は追加しません。削除・0件化・古い更新日時のファイル追加も取り込みます。不完全な走査や表示中の一覧より古い応答は件数判定に使わず、フィルター・プロジェクト・利用セッションが変わった応答も破棄します。比較対象は前回の応答ではなく表示中の一覧なので、再読込に失敗しても次回に再試行できます。件数だけの変化では自動追跡を予約せず、既存の選択・フォルダ展開を保ったまま一覧を更新します。

`frontend_web` と `frontend_avatar` の `AIファイル.vue` も、日時フィルター適用後の一覧件数と最終更新日時を更新条件にします。件数だけの変化では、残っている選択と手動のフォルダ開閉状態を保持し、最終更新ファイルの選び直しは行いません。古いセッション・日時フィルターの応答と非表示中の応答を破棄します。明示再読込の未取得値は `null` とし、実際の日時フィルター値である `-1`（当日以内）を使わないでください。

「閲覧軌跡」「AI検索軌跡」と関連ファイルへの移動ボタンは、エクスプローラーの開閉に関係なく表示します。閉じている間はバーガーボタンの右隣へ横並びにし、狭い画面では折り返します。開閉だけでは選択した軌跡を変更しません。

軌跡ボタンは一覧の開閉も兼ね、直下にファイル一覧を表示します。AI検索軌跡は検索結果の順、閲覧軌跡はengineのjournalからファイルだけを最近開いた順に表示します。journalはSpaceViewからpropsで渡し、一覧クリックも既存のselectExplorerを通します。閲覧一覧を開いている間は再訪による順序変更を止め、前・次で同じ2件を往復する状態を防ぎます。一覧外のクリックとEscで一覧だけを閉じます。`check-ai-search.mjs` はエクスプローラーを閉じたまま両一覧から移動し、再訪時の表示順も照合します。

ルート行も通常のフォルダと同じく、三角ボタンは開閉専用、フォルダ名ボタンは `select({type:'dir',path:''})`のルート移動に分けます。開閉ボタンを押しただけで宇宙を移動させないでください。ツリー行は `TransitionGroup` で高さと不透明度を240ms以内で変え、下の行も流れに沿って移動させます。手動開閉・ルート開閉・時刻検索の展開変更を同じ演出にし、OSの設定によって規定の演出を省略しません。検証では途中の高さと連打後の最終状態も確認してください。

エクスプローラーからの移動は `SpaceView.selectExplorer()` を通し、航路全体の完了まで選んだ項目を一覧の `selected` / `current` に保持します。途中で通るフォルダは宇宙だけに反映します。`navigating` の間は一覧の自動 `reveal()`（カーソル変更・展開・スクロール）を止め、利用者の一覧操作は有効に保ちます。連続選択時は古い航路の完了で新しい選択を解除しないでください。`check-warp.mjs` で深いフォルダ・別枝ファイルへの移動中も一覧の状態とスクロールが変わらないことを確認します。

grepは検索ボタンでのみ実行し、入力中は前回の結果を保持します。検索開始時に一覧を先頭へ戻し、展開状態をリセットしてルートを閉じ、「検索中…」を表示します。完了時はルートと一致ファイルの全親フォルダだけを開き、0件ならルートだけ開きます。結果表示後もスクロール位置は先頭にします。再検索・解除・検索方式の切替後に古い応答が展開状態や検索マークを上書きしないことも確認してください。

縦表示（画面の高さが幅以上）では、上左にエクスプローラー、上右に軌跡ボタンとリスト、下半分にファイルビューアを配置します。エクスプローラーを閉じても軌跡は右側を維持します。ただし、エクスプローラーを別窓へ出した間は、軌跡バーと再表示ボタンを縦横とも本体左端の16px余白へ寄せ、一覧を開いたときの宇宙中心も左側の占有領域を避けます。本体へ戻すと通常配置、別窓を閉じるとExplorer再表示ボタンを残す配置へ戻します。VR移行の矩形採取中と独立した軌跡窓の座標は変えません。別窓状態は再起動へ保存せず、起動時は従来どおり両バーを閉じます。回帰確認は `checks/navigation-parity.test.mjs`・`checks/workflow-components.test.mjs`・`checks/panel-lifecycle.test.mjs` です。両一覧の幅はそれぞれ画面幅の25%、高さは画面の中央までに制限します。ビューア表示中の宇宙の中心は、上半分で開いている一覧の間の中央です。ビューア非表示時は一覧の開閉に関係なく、画面全体の中央（横50%・縦50%）に固定します。

横表示では、左側にエクスプローラーと軌跡ボタン・リスト、右側に幅33vwのビューアを配置します。左の両一覧はそれぞれ画面幅の25%にし、宇宙の中心は開いている一覧の右端とビューアの左端の間に置きます。片側のパネルを閉じた分だけ空き領域を広げます。固定の33%・50%ではなく実際の一覧寸法から算出します。縦位置はヘッダーと下部操作ボタンを除いた作業領域の中央です。`SpaceView.layout()` がcenterX・centerYを返し、パンくずと `宇宙描画.js` のmeasureCoverで共有します。ワープ到着後の配置もplannedPreviewで同じ中心を求め、移動中の投影中心固定を維持します。`check-warp.mjs` は横1280×800・縦768×1000・狭い縦390×844で各パネルの全8開閉パターンを確認し、中心がパネルに隠れないことと一覧の配置・高さを検証します。画面は `temp/space-layout-check/` に保存します。検証画像名の先頭には日本時間の撮影日時と連番を付け、名前順で新旧が分かるようにします。一覧・軌跡・ビューアの文字は共通の `--file-font-size:10px` で揃えます。MonacoもこのCSS変数を読み、コードと簡易テキスト表示のサイズを一致させます。HTML・SVG・Office文書の表示内容は元文書の書式を維持します。

自動視点は `src/components/開発スペース/自動周回.js`、操作との連携は `宇宙描画.js` に置きます。軌道形状には遠点起算のケプラー方程式 `M = E + e sin(E)` を使います。遠点の速度は従来の1/3、近点は従来の1/6とし、速度差を圧縮して加速感を残します。接近中は実速度が増え続ける曲線を使い、近点直前で減速へ転じないようにします。物理公式どおりの一定面積速度にはせず、遠点では次の軌道への切替中だけ停止します。一周の軌道面は固定し、次の軌道面への変更は停止中に行います。船体の実座標から軌道を始め、1.1秒の位置固定旋回、軌道面へのロール合わせ、案内線の表示後、現在フォルダの中心を見続けて進みます。ファイル選択・ワープ・ドラッグでは彗星航行を中断し、画面非表示では描画ループも停止します。手動操作後は最後の操作から60秒経過して通常航行を再開し、それまでの待機中は低速回転を使います。ピンチとドラッグ終了時も停止期限を更新し、ファイル選択解除そのものでは期限を延長しません。`checks/auto-orbit.test.mjs` と `scripts/check-autodrive.mjs` で実座標・中心への視線・軌道の連続性と実画面での停止条件を確認します。

手動ドラッグの `orbitAround()` はワールド固定のY軸ではなく、現在のロールとパネルによる見回しを含む画面の上下・左右軸を使います。船体の実座標と視線を同じ角度だけ中心星の周囲で回し、中心の投影位置・周回距離を保ちます。`interpolateOrbit()` は最短回転で追従させ、真上・真下や上下反転の姿勢でもEuler角の個別補間による逆向きの動きを避けます。カメラのyawの符号だけを検査せず、手前側の星の投影位置がドラッグと同じ方向へ動くことを確認してください。`checks/warp-camera.test.mjs` は任意の姿勢・中心・パネルオフセットの投影を、`checks/manual-drag.test.mjs` は実エンジンのpointer入力からCanvas描画までと、クリック閾値・取消・ズーム・1分待機・2D中断を検証します。これらは実ブラウザーの画面撮影とは区別してください。

## 検証・配布

星・惑星・銀河の描画寸法はワールド寸法×透視倍率（焦点距離/奥行き）で決めます。最小表示サイズや選択時の上限で距離差を消さず、更新の強調も倍率だけで表現します。遠方は明るさを抑え、カメラ直前は滑らかに消します。銀河中心が背後でも手前に残る星は個別に描画・選択できます。`check-orbit.mjs` は実Canvasの描画呼出しで距離半分ならサイズ2倍となることと、銀河内の描画を確認します。

自動視点の最接近距離は遠点の18〜26%です。初回の軌道計算上の周期は48〜64秒で、実時間では全体の1/3速と近点の追加減速を適用します。星々の分布半径1500より内側まで入り込み、接近・通過・離脱が見える範囲を維持してください。全景の外から眺めるだけの距離に戻さず、`checks/auto-orbit.test.mjs` で `cameraPosition()` の原点からの距離を測り、分布の内側へ入ることを確認します。`dist` は描画上の注視点までの距離なので、実座標の代わりには使いません。

宇宙の中央にはルートを含む全階層でワームホールを表示し、ラベルは現在フォルダ名にします。子階層ではダブルクリックで1つ上へ戻り、ルートではワープしません。ラベルとツールチップに親フォルダ名を混ぜないでください。

宇宙表示の右下「視点移動」は利用開始ごとにONです。`開発スペース.vue` から `setAutoSpin()` を呼び、エンジンの通知でトグルとSpaceキー操作を同期します。OFFは自動移動を止め、手動操作は有効のままです。明示的なONは60秒の待機を解除します。ファイル選択中は通常航行を再開せず、低速回転を維持します。選択解除や階層移動で利用者のON/OFFを上書きしないでください。

起動時は現在の最終更新ファイルを一度表示します。自動表示中を示す `followedPath` と、最後に到着した `lastFollowedPath` は分け、手動操作やOFFからONへの切替で到着済みの記録を消さないでください。同じパスの通知や再開では再予約せず、移動先のフォルダで彗星軌道へ戻ります。別の最終更新ファイルは引き続き追跡し、手動待機・OFF中の未到着予約も保持します。追跡は直列に実行し、移動中の更新は最新の予約で上書きして、古い対象を開かないようにします。追跡開始時には一覧を再走査し、直前に新規作成されたファイルも取り込みます。進行中の走査が更新通知より前なら、両モードともfresh=1で1回だけ再検証します。通知後のfreshness走査は共有し、古い一覧に残る削除ファイルを開いたり、新規ファイル・同一ファイルの更新を捨てたりしないでください。モード切替中も受信済みの追跡先は保留へ戻し、古い航行を無効化して新モードで再検証します。未到着の更新と古いコールバックの寿命は分けます。プレビューの自動終了は「閲覧の3分無操作と自動探索」に従います。IDE内表示・自動探索ONの間だけ実ユーザー操作から3分で閉じ、別窓や自動探索OFFでは保持します。自動消去からの彗星軌道再開では同じ対象を再予約せず、新しい更新を待ちます。`node frontend_ide/scripts/check-autodrive.mjs` で一時プロジェクトと実ブラウザの仮想時計を使ってこれらの遷移を検証し、`temp/autodrive-check/<日時>_<連番>_autodrive-*.png` を撮影します。

複数更新は `requestFollow()` に更新順のパス配列で渡します。自動探索が動ける状態になったら再走査し、先行ファイルはカメラ移動やプレビューを行わず、親フォルダの経路とファイルの閲覧軌跡だけを保存します。最後のファイルだけへ実際に移動します。待機中にさらに更新が来た場合も先行分の経路を保持し、移動先は最後の新しい対象にします。`check-autodrive.mjs` は同じ秒の3件から前回最後のファイルを除外すること、先の2件が表示されないこと、別フォルダの経路保存、更新なしでの一覧保持、6件の小さいスクロール、縦横画面も確認します。任意配置のChrome / Edgeは `CHROME_PATH` で指定できます。

ワープの旋回計算は `src/components/開発スペース/ワープ視点.js` にあります。`cameraPosition()` で船体の実座標を復元し、位置を固定して1.1秒で目的地へ旋回した後、正面へ直進します。通常のカメラ補間も `interpolateCamera()` で実座標を補間し、注視点と角度の同時補間による横滑りを防ぎます。ドラッグだけは例外で、`orbitAround()` により中心星を軸に回り込みます。星までの距離を保って船体と視線を一緒に回し、ドラッグ後の実位置・向きを次の航行の出発地点にします。彗星飛行は楕円上の位置と速度を維持し、視線だけは常に現在フォルダの中心へ向けます。再開直後は位置を固定して約1.1秒で中心へ向き直します。計算した軌道線は `自動周回.js` の航行と同じ位置計算から385点を採り、新しい軌道の確定時だけ生成します。船は基準軌道点から軌道面の上向き法線へ、基準半径×tan(5度)だけ上げた実座標を飛びます。基準半径をcos(5度)倍して中心からの船体距離を従来どおり保ちます。初回と次軌道の計算では、この高さを含む船体位置が切替前と一致するよう軌道の基底を回転します。`宇宙描画.js` の `drawOrbitPath()` は基準軌道の座標を原点中心に0.90倍して船の内側へ寄せ、天体と同じ投影で淡い青の線だけを描き、背後の点や軌道の末尾と先頭を結びません。手動操作・ワープ・プレビュー・OFFで航行用の軌道を破棄します。表示用の線は約1.2秒のsmoothstepと軽いぼかしで消し、新しい線も約1.2秒で浮かび上がらせます。遠点では `hiding`（1.2秒の消去）→ `planning`（暗い状態で再計算）→ `aligning`（3.6秒のロール回転）→ `revealing`（1.2秒の表示）→ `flying` の順で進めます。自動探索ボタン上の状態表示は、軌道切替の全段階で「軌道計算と姿勢制御中」、航行開始後は「探索軌道航行中」に切り替えます。回転は2.7秒で目標角度を回転量の15%だけ越え、残り0.9秒で一度だけ戻して水平に整えます。切替中は船体を遠点に固定し、視線も中心に保ちます。`orbitLevelRoll()` は軌道面の法線から水平になる最短ロール角を求めます。`cam.roll` を天体・遠景の投影へ同じように反映し、軌道面の上側が機体の上になるようロールを合わせます。案内線だけの見かけの回転は行いません。`orbitVisibility` とフェーズを使い、機体回転中には新しい線を出しません。星系が変わった場合は旧線を持ち越しません。進行方向の接線を向くと星系を背にして黒い画面になるため、接近・通過・離脱と次の軌道への切替でも中心注視を保ってください。手動回転の軸は彗星飛行中は現在フォルダの中心、接近後は目的の星です。全体表示は外側の観測位置へ向いて前進し、そこで中心へ向き直ります。フォルダ到着時も船首方向を引き継ぎます。

親へ戻るワープでは、現在フォルダ名を付けた中央の星（`world.gate`）だけ接近距離を画面幅から求めます。中心球だけでなく外周リングの線幅込み直径（`2.07 × R`）が接近時に約25%へ収まる距離を `framingDistance()` で計算し、`cockpitLook()` による視線の偏りも補正します。既に近い時は滑らかに離れて同じ距離へ合わせます。この帰還だけCanvasの拡大を2倍にし、外周の最大幅を約50%にします。淡い背景光の透明な外縁はリングより広いため、中心球・明るいリング・背景光の寸法を区別してください。子フォルダ銀河への接近距離・2.6倍のワープ、同階層ファイルの接近、通常描画のファイル星のサイズは変えません。`checks/warp-framing.test.mjs` は横1280×800・縦768×1000・狭幅390×844・超横長2560×720と視線偏り、実Canvasのarc外周と中心球、至近距離からの調整、接近中の取消・モード変更・選び直し・破棄、他天体の互換性を確認します。テストの描画呼出し計測は実ブラウザ撮影の代わりにはなりません。

手動選択・閲覧軌跡・AI検索軌跡・最終更新の自動追跡は `goTo()` を共有します。別フォルダへは共通の親を経由し、1階層ずつ旋回・前進・ワープします。目的フォルダ内のファイル接近には常に `transition:false` を使い、Canvasの拡縮・暗転・ぼかし・放射状のワープ光跡を再生しません。接近済みの同一ファイルの手動再選択は移動を省略します。ビューアの閉じる操作・3分の条件付き自動終了は、現在の階層・船体位置・船首方向を保ちます。閉じる操作で移動中なら、その場で航行を取り消します。連続選択でも古い航路が後からプレビューを開かないよう世代番号で無効化します。未選択状態の再走査を「閉じる」操作として扱わないでください。自動追跡が自分の再走査で取り消されてしまいます。

パネル開閉では船体を動かさず、`cockpitLook()` で操縦席から見回す回転を加えます。透視投影面の中心は画面中央に固定し、空き領域へ移すのは船首の見える位置です。平行移動による全景の横滑りや、ビューアが開いた瞬間の中心ジャンプを避けます。`SpaceView.layout({preview})` が返す空き領域の中央とパンくず配置は維持します。航行中は `warpProjection` に視線配置を固定し、フォルダ間のワープでは不可視の間だけ到着時の配置へ切り替えます。

`checks/warp-camera.test.mjs` は実座標・正面への直進・航行の位置固定旋回・手動周回・視線回転の距離/角度保存を確認します。`check-warp.mjs` は実際のエクスプローラー行クリック、同階層の演出なしの接近、深いフォルダ・別枝・選び直し・閉じた時の現在地保持・左右ドラッグ・縦横の配置を検証します。`check-autodrive.mjs` は同階層の自動追跡にもワープ演出がないこと、3分の条件付き自動終了、更新追従、予約変更を確認します。ワープ光跡の長さは従来比1.8倍を維持します。

右下の「高速ワープ」は利用開始時OFFです。ONでは `goTo()` による別フォルダのファイル選択（エクスプローラー・閲覧軌跡・AI検索軌跡）を、目的フォルダまで1回の `travelTo()` にまとめます。中間階層を表示せず、到着後に `destinationFile` を新しいworldから引いてプレビューを開きます。到着後のファイル追尾や追加接近を行わず、フォルダ全景を維持してください。同階層の一覧選択は高速ワープのON/OFFに関係なく旋回・接近します。最終更新の自動追跡も高速ワープ設定に従い、フォルダ自体の選択は通常の階層順ワープです。OFFへ戻すと通常の階層順ワープになります。`check-warp.mjs` で既定OFF、深い階層・別枝・親フォルダへの1回の移動、同階層の旋回・直進と接近済みファイルの再選択、選び直しによる取消と到着後の視点固定を確認します。

`frontend_ide/README.md` の起動・検証コマンドを使用します。画面配布更新の際はVue bundleを生成します。VS CodeのCode / Liveにも同じbundleを含めるため、拡張配布には `frontend_ide/host` で `npm run package` を実行します。拡張IDは変更しません。IDEのVS Code拡張は作りません。

実画面では手動開始、バーガー初期閉、5種類の起点プリセット、grepマーク、選択・解除の視点移動、Codeオフライン、WebのLiveタブ終了時の音声停止を確認します。ElectronはCode / Liveの個別終了、IDEの「終了」で子窓を閉じて起動画面へ戻ることを `check-windows.mjs` で確認します。`AIDIY_TEST_CLOSE=title` を環境変数に設定するとウィンドウの×からの全窓終了も検証します。×・Alt+F4はElectronメイン側のcloseイベントで確認し、取消では作業状態を変えません。`check-core-stop.mjs` はOSダイアログの選択だけを代行して、確認文言・取消・承認・重複防止と起動画面からの再利用も検証します。終了中の子窓起動はIDE側のrevisionで無効化し、モード・startedAtが変わった子窓はメインプロセスの監視で破棄します。マイク権限・ソケット・非同期初期化はコンポーネント破棄との競合も確認します。

コアの接続状態と作業セッションの寿命は分けます。利用開始後のコア停止では `connected` だけを落とし、`active`・`mode`・`startedAt`・再接続要求を維持します。コア復帰で起点を更新するとVue画面が再生成され子窓も閉じるため、同じ起点で再接続してください。`node frontend_ide/scripts/check-core-stop.mjs` は利用者のコアを停止せず、検証用サーバーの停止・再起動でIDEのファイル表示とCodeの窓・下書きが残ることを確認します。

時刻検索のプリセット（起動・10分・1時間・今日・解除）と日時の直接変更では、まずルートを閉じ、全行のleave完了を待ってから60msの間隔を挟み、一致件数があるフォルダだけを全祖先まで展開します。ルートを開き直し、一覧は先頭へ戻します。連続選択は最後の期間を採用し、検索方式変更や手動操作・部品破棄では予約を取り消します。同じプリセットの再クリックでも再計算し、一致なし・解除ではルート直下だけを表示します。選択ファイルや宇宙の現在地は変更しません。`check-ai-search.mjs` で手動展開のリセット、深い一致先、期間変更、0件、再クリックを確認します。

## 時刻検索の期間と軌跡

`ファイル一覧.vue` の開始・終了は `datetime-local` の秒入力とし、閲覧端末のタイムゾーンを維持します。`ファイル日時.js` の `parseLocalDateTime()` は存在しない日時・途中入力を不正として扱い、終了のみ指定した場合や逆転した期間も画面でエラーにします。終了空欄だけが上限なしです。終了は内部で次秒（+1000ms）未満とし、ミリ秒未満を含むファイル時刻でも入力秒の末尾まで含めます。`inTimeRange()` を一覧・2Dの `フォルダページ構成.js`・3Dの `宇宙描画.js` で共有します。APIの走査条件や最終更新監視にはこの終了日時を渡しません。

時刻の結果は「時刻軌跡」、grepの結果は既存の「検索軌跡」と表示します。内部の `since` / `search` 識別子と展開状態の保存形式は変更しません。終了値は `marks.until` へ渡し、省略した旧形式は上限なしとして扱います。再走査・フィルター変更時には時刻の候補だけを再集計し、表示中の閲覧／AiDiy軌跡を勝手に切り替えません。開始プリセットは終了を維持、解除・利用開始は終了を空にします。

確認は、開始のみ、両端が同秒、終了秒の小数部と次秒、逆転・途中入力・不正日付、終了を消す、プリセット・新しい利用開始、再走査とフィルター変更、grep/AiDiyとの切替を対象にします。本体・ピン留め先の入力欄とエラー、一覧・2D・3D・軌跡の対象一致を確認してください。

## AI検索の変更・検証

AI検索を選んでいる間はファイルツリー・ルート行・最終更新行を隠し、検索入力・履歴・結果にパネル全体を使います。時刻検索・grep検索へ戻すとツリーを再表示し、検索結果や軌跡は保持します。

`frontend_ide/ファイル機能/ai-search.mjs` が `/api/ai-search` のPOST（依頼）とGET（結果確認）を受け持ちます。共通設定の `PORT_TOOLS` を使って `aidiy_code_agents/config` と `/run` を呼び、Codeの既存セッションは再利用しません。IDEの利用状態とHost / Origin検証を通し、ブラウザから接続先・任意の結果パスを指定できない構造に保ってください。

依頼ごとにID・秒形式の保存先・5分の期限を発行します。保存先はプロジェクト内のtempを実パスで確認し、`.request` の排他作成で重複を避けます。結果のrequestId・query一致、相対パス、実ファイル、リンク先の境界、件数・サイズ、routeとfilesの一致を検証してから返します。タイムアウト後も同じ依頼のGETで再確認できます。新しい依頼を始めても古い出力が新しい結果へ混入しないことを維持してください。

`AI検索パネル.vue` が2秒間隔の確認と世代管理を行い、完了した結果だけを `ファイル一覧.vue` へ渡します。`FileExplorer` は検索理由・親フォルダの関連件数・成功結果の保存・軌跡切替を担当し、`SpaceView` を通じて `宇宙描画.js` のmarksとrouteへ通知します。`検索経路.js` が各階層の中央から直下の関連フォルダ・ファイルへの描画順を作ります。閲覧航路のvoyages/journalは変更しません。AI結果の到着でファイル選択やgoToを実行しないでください。

結果JSONの `title` はユーザーの要求からAIに生成してもらう検索タイトルです。目安30文字以内、最大80文字で依頼し、空白・型・長さを検証して履歴へ保存します。履歴一覧・削除確認・選択結果・AI検索軌跡リスト上部はこのタイトルを表示し、元の `query` も保持して再検索とツールチップに使います。旧結果のtitle欠落はqueryを1行80文字以内にした表示へ補完し、過去の履歴を読み込むためだけにAIを実行しません。`checks/ai-search.test.mjs` で保存・再起動・不正タイトル・旧形式を、`check-ai-search.mjs` でタイトルによる履歴選択と軌跡の復元を確認します。検証画像は日時と連番付きで `temp/ai-search-check/` に保存します。サーバー側を変更した時はIDEサーバーを再起動して新しい依頼形式を反映します。

`checks/ai-search.test.mjs` で期限・遅れた結果・不正結果・リンク・セッション・API・航路を検証し、`scripts/check-ai-search.mjs` で結果到着時にワープしないこと、マーク、切替、順番に閲覧、再検索時の古い結果抑制を撮影します。`scripts/check-ai-search-live.mjs` は実エージェントを使うため明示実行専用です。

検索履歴は `ファイル機能/ai-search-history.mjs` がプロジェクト内 `_AIDIY/aidiy_ide/file_searches/<依頼ID>.json` に保存します。保存先の作成・境界確認は `ファイル機能/ide-data.mjs` の `ideDataFolder` に共通化しています。`/api/ai-search/history` のGETで一覧、`?id=`付きGETで理由と軌跡、DELETEで確認済みの1件を削除します。既存のHost / Origin・利用開始チェックを共用します。保存先の各段階で実パス境界を検証し、原子的な一時ファイル→renameで保存します。削除はIDだけの削除済み記録に置換し、元のtempから復活させません。旧保存先と旧temp結果は読み込みません。履歴読込ではパス形式・理由・routeの整合を検証し、現在は存在しない対象も検索当時の情報として残します。

`AISearchPanel` は履歴の取得・選択・削除確認を担当します。初期復元は現在の検索方式・閲覧軌跡を変更せず、明示選択だけがAI検索軌跡に切り替えます。`FileExplorer.acceptAI` は結果を受け取り、位置移動なしでmarksとrouteを更新します。新規検索開始・部品破棄では古い履歴応答を無効化してください。履歴の取得失敗と空一覧を区別し、既存のマークを消さず再読込を案内します。テストでは別プロジェクト分離、再起動、旧結果を取り込まないこと、削除後の再取込防止、異なるマークへの切替、削除取消・確定、履歴切替で視点が動かないことを確認します。

## 更新履歴の比較を変更するとき

`ファイル機能/file-history.mjs` は `/api/file-history?path=...` で保存版一覧、`version=...` 付きで旧版・現在の全文を返します。プロジェクトとファイルの祖先にある `.aidiy_backup/YYYYMMDD/HHMMSS[.all][.コメント]` のみを調べ、各保存版の同じ相対パスを照合します。全体のバックアップ内容を再帰走査せず、最大5000保存版で打ち切りを明示します。IDはバックアップ相対パスのSHA-256ですが、取得時にも候補一覧との一致と実パス境界を再検証してください。外部リンク・保存版外のリンクを拒否し、利用状態と既存のHost / Origin検証を通します。比較は各1MBまで、UTF-8 / Shift_JISを読み、切り詰めません。

`ファイルビューア.vue` はテキスト表示時に履歴を確認し、存在する場合だけボタンを出します。IDEの比較対象は `閲覧セッション.vue` が保持し、通常表示と比較を同じ閲覧セッションとして管理します。MonacoのDiffEditorを読み取り専用・左右固定・空白差分を無視しない設定で使い、未変更行の位置合わせとスクロール同期を任せます。切り替え時の古い通信を中断し、閉じる際はエディターと両モデルを破棄します。IDE内の比較も `閲覧セッション.vue` の共通待機処理に従います。条件・操作判定・取消は「閲覧の3分無操作と自動探索」を参照し、比較だけの5分タイマーを追加しません。

Monacoの共通読込は `src/components/ファイル閲覧/コード表示.js` に集約します。並行読込と成功結果だけを共有し、読込失敗を永続的にキャッシュしないでください。失敗後の再試行ではAMDローダーの失敗状態をresetし、配信URLにも読込時の識別子を付け、セットアップ前の古いモジュールを使わないようにします。`/monaco/` の資産は再検証を要求するキャッシュ設定で配信します。比較画面の「再試行」は画面の再読み込みなしで再取得し、依存不足が続く時はセットアップ確認を案内します。通常ビューアは読込失敗時も簡易コード表示を維持します。

APIとパス境界は `checks/file-history.test.mjs`、共通読込の失敗と復旧は `checks/monaco.test.mjs`、実画面は `node frontend_ide/scripts/check-file-history.mjs` で確認します。ブラウザー検証は専用の一時プロジェクト・ブラウザーを使い、ローダー・比較モジュールの読込を意図的に止めて「再試行」で復旧することも確認します。任意配置のChrome / Edgeは `CHROME_PATH` で指定してください。エラー・横・縦の画像を `temp/file-history-check/` に日時・連番付きで保存します。実利用中のブラウザーのビューポート寸法を固定しないでください。API変更後は対象IDEサーバーを再起動します。

## ファイル解析の保存・表示を変更するとき

`ファイルビューア.vue` の「AI解析」ボタンから、`App.vue` が保持する `ファイル解析ダイアログ.vue` を開きます。対象のプロジェクトとファイルを固定し、ビューアの3分の条件付き自動終了でもダイアログを消さない構成です。AI解析ボタンとダイアログの見出しにはアイコンを表示しません。入力欄は「概要の分析指示（テキスト）」と明記し、概要（`summary` と `content` 内の内容説明）だけへの指示として扱います。表示URLとその根拠となる関連ソースの調査、指定JSON形式・保存方法は独立した定型文で依頼し、概要の指示で上書きしません。初回指示は画像類とソース類を分け、保存済み指示があれば必ず優先します。Markdown本文はHTMLを無効化し、外部画像を読み込みません。

ビューア本体のボタンは、Browserと同じく「AI解析中…」「AI解析済」「AI解析 要確認」を表示します。`ファイル閲覧/ファイル解析状態.js` が表示中のプロジェクト・ファイルだけを軽量GET（`status=1`。本文・依頼文・全原本は転送しない）で確認し、別ファイルから戻った時や再読込時に復元します。解析ダイアログのPOST後は同じ公開元の通常／ピン留めビューアへ再取得を通知します。通知の内容で結果を書き換えず、サーバーの状態を確認します。途中の保存結果があっても、`waiting` または `monitoring` の間は解析中を維持し、待機中は2秒、取得失敗時は10秒で再確認します。ファイル移動・ビューア終了で解除するのは表示用GETだけで、バックグラウンド解析は止めません。解析中ボタンも押せるため、進行状況・結果を開けます。状態遷移は `checks/file-analysis-status.test.mjs`、通常／ピン留めの実Vue表示は `checks/preview-actions.test.mjs`、依頼後の通知は `checks/file-analysis-monitor-ui.test.mjs` で確認します。`scripts/check-viewer-floating.mjs` は実画面の解析中・完了表示も確認します。

`ファイル機能/file-analysis.mjs` は `/api/file-analysis` のGET（復元・結果確認）、PUT（指示保存）、POST（解析依頼）を担当します。既存の `runSearchAgent` を使い、対象と指示を含む依頼ID付きJSONをtempへ出力させます。ブラウザを閉じてもサーバー側が最大5分間確認し、最新の成功結果を `_AIDIY/aidiy_ide/file_analyses/<相対パスのSHA256>.json` に保存します（`ideDataFolder` を共用し、旧保存先は読み込みません）。前回指示・本文・日時・対象の更新日時とサイズを保持し、失敗時に成功結果を消さないでください。保存先の実パス境界を確認し、ファイル別の書込キューと一時ファイルからのrenameで指示保存・結果到着の競合を防ぎます。

ページ関連候補（`isPageSource`）は、内容・関連ソース検索・URL調査をそれぞれ含む独立した3件を同時に実行します。`.py`等は1件です。各実行に固有の依頼ID・結果JSON・AbortControllerを割り当て、3件の原本を同じファイル記録の `run.attempts[].result` に別々に保存します。表示用の合成は永続化せず、GET時に `ファイル解析結果.mjs` で生成します。生のHTTP成功ではなく、依頼ID・対象・指示・非空本文・サイズ・パス境界を検証したファイルを成功条件にします。1件の成功後も他の実行を続け、各原本は初回検証後に上書きしません。表示はURL→概要→関連ソースの順で、URLと関連先の重複を統合しつつ解析番号別の根拠をすべて保持します。各解析の本文原本も開けます。新しい依頼と前回の成功結果は混ぜず、新規成功がない間だけ前回結果を表示します。不正JSONでも他の実行や修正が続いていれば監視を続けます。同一ファイルの二重開始を拒否し、同時5ファイル（ページ候補は最大15実行）の上限を維持します。過去の非ページ判定だけで本数を減らすと、呼び出し元追加を見落とすため、そのキャッシュは使いません。

監視期限・利用終了時だけ、未終了のHTTP実行の停止を要求します。Toolsの `/run` は切断を検知して所有CLIを終了しますが、画面には確認前の「停止済み」ではなく「停止要求済み（終了未確認）」と表示します。結果が先にそろっても `monitoring` が真ならHTTP終了応答・期限の監視を続け、二重開始を拒否します。既存APIはPIDやheartbeatを返さないため、監視表示は接続・設定確認、実行応答待ち、応答受信、結果検証の状態です。HTTP 200の `status:NG` や利用不可を失敗として識別し、実行成功後の履歴保存だけが失敗した場合も、結果ファイルが有効なら採用します。

解析の実行・監視・結果保存はIDEサーバーが所有します。ダイアログを閉じる、別ソースを開く、画面を再読込する操作では中断せず、同じファイルの再表示時に進行中の実行と前回結果を取得します。画面の一時的な取得失敗は自動再試行し、保存済み指示や編集中の入力を既定文で上書きしません。初回取得に失敗した状態で未変更の既定文のまま閉じる場合はPUTを送らず、保存済み指示を保持します。編集した入力は保存対象とし、保存失敗時は入力を残して再試行できます。利用終了・IDEサーバー終了では停止を要求します。サーバー終了後の実行継続やプロセス監視の復元は行いませんが、保存済み成功結果と各実行の成否は再起動後も閲覧できます。実行中だった記録は中断と表示し、動作中と偽って表示しません。

解析結果の `displayUrls` は `{url,label,reason?}` の配列（reasonは画面ごとの参照経路・設定と行番号）、`displayUrlReason` は根拠・未確認事項またはURLを特定できない理由です。`viewer/表示URL.mjs` をサーバー・画面・Browserで共用し、HTTP(S)の絶対URLだけを1原本につき最大20件（3件の合成表示は最大60件）に正規化します。認証情報・秘密クエリ・未解決の動的パラメーターなどは除外し、URL部分の不正で正常な解析本文を失わないようにします。旧記録の欠落フィールドは空として扱います。

`viewer/表示URL.mjs` の `isPageSource` を全経路で共用します。HTML / Vue / JS・TS（JSX・TSX、MJS・CJS・MTS・CTSを含む）/ Svelte / Astroは調査候補であり、拡張子だけでページの有無を決めません。宣言ファイル（.d.ts等）・画像・文書などからURLを探索しません。ページ関連と確認できた場合は逆import・再export・HTML script参照から利用画面までたどり、共有部品の複数ルート・alias・base・hash/history方式を確認して各URLと根拠を保存します。未解決ID・host/port・別アプリの設定は推測せず、探索範囲と省略を明記します。

ページに関係ない.py・CRUD・API・CLI・サーバー専用JS等は、対象を直接呼び出す/importする元と、対象が直接呼び出す/importする先の1次レベルだけを調べます。祖父（元のさらに元）・孫（先のさらに先）への再帰探索や、CRUD→API→画面のURL探索はしません。本文は「関連ソース（1次レベル）」に呼び出し元・呼び出し先、参照種別・関数・相対パス・行番号を分けます。分類不明も1次に留めます。`relatedSourceScope` はpage（画面まで）/ direct（1次）/ none（内容のみ）で保存・表示し、旧結果で欠けている場合は範囲を断定しません。direct / none結果のURLは採用しません。

`server.mjs` の `/api/preview` はページ関連ソースの保存URLがある場合に `{kind:'analysis',routes,stale,reason}` を返し、無い場合はHTML / Vueだけ従来表示へ進み、JS等はコードのまま保持して起動ボタンを出しません。ファイルビューアはコード表示でも画面URLを示し、複数URLの選択を表示切替後も保持します。解析ダイアログを閉じると同じ対象のURLだけを再取得します。遅い応答・別ファイル・破棄後の結果を表示しないでください。解析URLがIDEと同じoriginを指すiframeには `allow-same-origin` を付けません。

Browserの既存起動APIには省略可能な表示URLを追加します。Webはクリック中に空窓を予約し、元ファイルとtools接続を確認してから遷移します。Electronは信頼済み送信元・プロジェクト実パス・利用セッション・接続を再検査します。URLを開くのは明示操作時だけで、解析はサーバー起動・通信による到達性確認を行いません。

表示URLの回帰確認は `node --test frontend_ide/checks/file-analysis.test.mjs frontend_ide/checks/display-urls.test.mjs frontend_ide/checks/preview-actions.test.mjs frontend_ide/checks/browser-display-url.test.mjs`。実Vueのコード／表示切替・複数画面・保存結果・破棄は `node frontend_ide/scripts/check-display-urls.mjs` の隔離ハーネスで確認します。実AIによるURL推定の正しさや実プロジェクトのログイン・サーバー稼働は、この模擬試験の合格に含めません。

## Code / Live の演出を変更するとき

表示寸法・配色・キーフレームは `frontend_ide/src/components/共通表示/会話表示.css`、Vueへの送受信連携は `src/components/コード/会話到着演出.js`、文字送りと枠飛行は `host/src/arrival-effect.ts` にあります。旧画面を参考にするときも `frontend_vscode` を実行時依存にしないでください。

入力は送信時の入力欄位置を予約し、同じ本文が戻ったユーザー発言へ560msで飛ばして白い光とぼかしから表示します。Codeの入力履歴は右側70%以内、回答は左側90%以内です。回答は中央の高さ30vhの黒地・白枠へ文字送りし、全文表示後3秒保持して履歴へ移します。Code / Liveとも後続回答は順番待ちにし、入力通知や後続回答で3秒待機を打ち切りません。Codeで同じ状態を再受信しても再演出せず、同じ発言の本文が更新された場合だけ最新の全文表示から数え直します。保存済み会話の読込では再演出しません。会話切替・切断・破棄・画面非表示では順番待ちを含む飛行、文字送り、タイマーを解除します。`check-chat-effects.mjs` は連続する回答それぞれの文字送り完了から飛行開始までを実ブラウザの時計で計測します。

初期画面は3行を12秒周期で順に表示し、入力を始めたら全行表示で止めます。入力欄を空にしても再開せず、新しい会話で再開します。Codeの処理中は入力欄上下の1px線を、シアンと白が4.2秒周期で逆方向に通過します。進捗はSTX/ETX/CANで文字送りを開始・終了し、状態通知で同じ文字を二重追加しないようにします。

画像は `host/media` と `host/aidiy_live/media` の元画像を `scripts/build.mjs` から共通・両拡張の配布先へコピーします。画像追加時は `server.mjs` の配信許可一覧も更新してください。検証はREADMEの `check-chat-effects.mjs` と `check-electron.mjs` を使用します。

## BrowserパネルとMCP接続

Browser AI解析の実行はプロジェクト内のURL別ジョブとしてサーバーが保持します。解析子窓を閉じても処理は自動継続し、継続専用ボタンはありません。別ページへ移動しても処理を取り消しません。Browserの表示URLが変わっても解析子窓は開いた時点の対象URLを保持します。別のURLを解析する場合は子窓を閉じ、目的のページから開き直します。関連ソースのIDE連携は現在のBrowserのURL・セッションも照合し、移動後の古い対象からは操作できません。元URLへ戻ると、そのページのボタンを「解析中…」「AI解析済」「AI解析 要確認」に復元し、クリックで進行状況・保存結果を表示します。複数ページは独立し、同じURLの同時依頼は重複させません。query・hashを含む正規化済みURLとプロジェクトをキーにします。

通常操作欄とF11ヘッダーは、表示中ページの状態だけをGETの `status=1` で確認します。待機中だけ2秒間隔、初回取得・待機中・再確認中の一時失敗は10秒間隔で再確認します。同じ公開元の解析子窓は依頼の応答後にURLだけを通知し、通常操作欄・F11ヘッダーの表示中URLが一致する場合だけ状態を即時再取得します。通知のジョブ状態や結果を信用して表示を書き換えず、サーバーの応答を正本にします。ページ・セッション変更時は古いGET購読を解除して新しい対象を確認し、操作欄の非表示・利用不可・破棄時は購読を止めます。解析子窓や下書き連携子窓を開いたこと自体では購読を止めず、操作欄が表示されている間は表示中ページの状態を引き続き更新します。定期応答には解析本文・ソース一覧・依頼プロンプトを載せません。古いURL・セッション・破棄後の応答は適用しません。失敗や期限切れで前回の成功結果を消さない構成です。実行中の不正JSON・未完成の結果は待機状態のまま内部監視で再確認し、正常化した結果だけを保存します。エージェント終了後も不正なら失敗を確定して再解析を許可します。期限は結果の読取や画面のGETとは独立したタイマーでも監視し、期限切れでは未完了の実行要求にAbortを送り、遅い結果は採用しません。

単独Browserのアプリ終了、起動元IDEの終了・利用終了では、処理の継続を保証しません。利用セッションが変わったジョブには中断を要求し、遅い結果を保存しません。完了済み結果は再起動後も同じURLから取得できますが、未完了ジョブを自動で再実行しません。検証は `checks/browser-analysis-recovery.test.mjs`、`checks/browser-analysis-background.test.mjs`、`checks/browser-analysis-status.test.mjs`、`checks/browser-analysis-ui.test.mjs`。実画面確認用の `scripts/check-browser-analysis.mjs` はページ移動・復帰時の表示も扱います。

Browserの「AI解析」は「表示中のURL」と「関連ソース」だけを表示します。ソース側の解析・表示URL候補とは別です。表示URL・タイトルから、現在のプロジェクト内のソース・router・サーバー設定・import関係を読み取り探索し、実在する関連ファイルを保存します。独立した概要欄は表示せず、既存のsummaryは補足記録として保存互換性を維持します。外部ページへのアクセスや操作、ソース変更は行いません。外部サイトなどで対応を確認できないときは関連ソースを空にし、理由を示します。

関連ソースのクリック連携は、IDEから起動したBrowser（タイトルが `AiDiy IDE / Browser N`）だけです。起動元IDE・プロジェクト・利用セッション・現在の解析結果を照合してファイルビューアへ表示します。単独Browserは一覧を表示するだけで、IDEを自動選択・自動接続しません。AI解析を開くときに既存のloopback・トークン付き共有基盤で同じ実パスのIDEの起動状態だけを確認し、起動中なら「IDEのBrowserから開くとビューアー連携できる」と案内します。IDEが未利用・オフライン・tools未接続なら先にオンライン利用とtools接続が必要な旨を表示します。Code / Liveの起動は検出の条件にしません。別プロジェクト・終了済みIDEは案内対象外です。検出失敗は解析を妨げず、起動中と断定しません。状態を再確認する場合は解析ダイアログを開き直します。

案内表示の確認は `node --test frontend_ide/checks/browser-viewer-guidance.test.mjs frontend_ide/checks/browser-analysis-ui.test.mjs frontend_ide/checks/browser-analysis-source.test.mjs frontend_ide/checks/browser-draft.test.mjs` と `node frontend_ide/scripts/check-browser-analysis.mjs`。隔離した模擬APIと実Vueを使い、未解析時・未連携・同じIDE起動中・IDE未利用の表示、非連携時にソース選択を送らないこと、遅い検出中のページ変更・閉鎖を確認します。実Electronの窓間フォーカス・実AIの探索精度は別途確認してください。

Electronで選択HTMLをBrowserへ渡すときの例外は `viewer/登録HTMLルート.mjs` に集約します。作業ルートの `frontend_web/public/` 配下だけを対象に、`src/router/*.ts` の `createStaticAliasRoute` と、登録Vue画面の `frameSrc`（`baseUrl` にHTMLの相対パスを足す形式） を使うiframeを照合します。登録に一致したHTMLだけ、`vite.config.ts` の `PORT_WEB`（既定8090）の対応ルートを開きます。ソースを実行して判定しません。未登録HTML・他フォルダ・コメントアウトされた登録は通常のfile URLです。Webサーバー停止中は理由を表示し、file表示へ暗黙に戻しません。ルート側の認証は通常どおり適用します。判定の検証は `node --test frontend_ide/checks/registered-html.test.mjs`、Electronでの通常HTMLとの切り替えは `node frontend_ide/scripts/check-browser.mjs` で確認します。

Browserの画面は `src/components/ブラウザ/ブラウザパネル.vue`、WebContentsViewは `デスクトップ/ブラウザ.cjs`、CDP中継は `デスクトップ/ブラウザCDP.cjs` が所有します。通常画面・VRの「Browser」とHTML/HTMの「ブラウザ」ボタンから起動します。既存のコード・表示プレビューは維持します。Web起動では新しいタブを開くため、クリック内で空タブを予約してからtools接続とプレビューURLを確認します。

### Browserの撮影結果表示

通常窓とF11ヘッダーは、撮影ボタンと「保存済み」を同じ折り返し単位にして隣接表示します。撮影IPCの成功と保存パスを確認してから表示し、保存先はツールチップに残します。再撮影中・失敗・保存パスのない応答では表示せず、以前と同じ保存パスの状態通知でも成功表示を戻しません。別rendererで完了した新しい保存パスは状態通知から反映します。メインフレームのページ移動・履歴移動・クエリやハッシュ変更・再読み込みで撮影パスと表示をリセットし、iframe内の移動やF11の表示切替では維持します。移動前に撮影・保存を始めていた場合は、同じURLへ戻っていても遷移番号で失効させ、古い完了通知を表示や下書きの画像添付に戻しません。保存済みの画像ファイル自体は削除しません。

`node --test frontend_ide/checks/browser-capture*.test.mjs` は成功・失敗・連打・古い状態通知・再試行・破棄・ページ移動と撮影／保存の競合を通常窓とF11ヘッダーで確認します。`node frontend_ide/scripts/check-browser-capture.mjs` は実Vue・模擬IPCを使い、幅1200px / 520pxでボタンとの隣接・撮影中・保存成功・失敗・再試行・移動時のリセット・同じURLへ戻った後の古い成功応答を確認し、`frontend_ide/temp/browser-capture-check/` に画像を保存します。配布buildと実プロジェクトへの保存は行いません。Chromiumを起動できる環境が必要です。`--compile-only` は画面コンパイルだけを確認します。

### Browserの要素連携

開始時は `DOM.enable` に続けて `DOM.getDocument({depth:0})` を待ち、CDPのdocument IDを登録してから検査モードにします。`DOM.enable` だけでは `Overlay.nodeHighlightRequested` が届かないため、説明枠が初期案内のままになります。最初のホバーは `Overlay.setInspectMode` の応答より先に届く場合があるので、コマンド送信直前に受信を有効にします。独自の説明枠が要素情報と位置を更新するため、Chromium標準の説明は `showInfo:false` のままとし、重複させません。

通常操作欄とF11ヘッダーは「AI解析 → 撮影 → Code / Liveへ → 要素連携」の順です。要素連携はAI解析とは独立し、`デスクトップ/ブラウザ要素連携.cjs` が既存のページ用CDP接続で `Overlay.setInspectMode` を開始します。選択中だけ `ブラウザ要素パネル.cjs` がページ内に一時的な説明枠を表示し、最上部に「項目選択中　esc=キャンセル」を示します。マウスを重ねた要素を強調し、説明枠にはセレクター、寸法、計算済みCSSの一部、HTMLの抜粋を表示します。説明のためのElectron別窓は開きません。クリックはページのリンク・送信処理へ渡さず、説明枠と選択モードを解除してCode / Live下書き連携の専用子窓を開きます。背景のWeb本文は隠したり縮めたりせず維持します。連携先と内容を確認して「下書きへ追加」を押し、AIへの送信はCode / Live側で行います。既存の下書きは保持します。

取得するのは表示中DOMで、元のVue / TSソースとの対応は保証しません。選択ID、session / tab_id、クエリ・フラグメント・認証部を除いたURL、セレクター、タグ、許可した属性、位置・サイズ（CSS px）、表示文、HTML、計算済みCSSを扱います。撮影画像・Cookie・Storage・入力値は取得しません。HTMLは16,000文字・160ノード・深さ8までで、上限を超えた場合は省略を明記します。script / style / iframe本文、入力値、編集可能領域、非表示の枝、data属性・イベント属性等を除外します。代表的な秘密値もマスクしますが、任意の文章から機密情報を完全には検出できないため、連携内容を下書きダイアログで再確認します。

Esc、ボタン再押下、要素の選択完了、ページ遷移・再読込、切断、最小化、終了で選択モードと説明枠を解除します。説明枠は入力を受けず、×ボタンはありません。下書き連携子窓は閉じる・ページ遷移・切断などで選択情報も破棄します。解除の `Overlay.setInspectMode` には `mode: 'none'` と `highlightConfig: {}` の両方を渡します。Chromiumは解除時も設定を検証するため、省略すると選択とクリック抑止が残ります。古いホバー結果・選択IDは新しい選択やページへ流用しません。F11ヘッダーから開始しても、連携先の選択は本体Browserを親とする専用子窓で行います。共有CDPをdetachしたり、他の利用者向けにDOMドメインをdisableしたりしません。外部ページへpreloadやIPCを追加せず、要素の読み取りと説明枠の操作は隔離worldで行います。説明枠のDOMはページと共有されますが、内容はclosed Shadow DOM内へtextContentで表示し、HTMLとして実行しません。説明枠はpointer-events:noneでフォーカス・クリックを奪わず、popoverを使う場合もbackdropは透明かつ操作を遮らない設定にします。説明枠自体は選択情報から除外し、解除時にDOMとscroll / resize購読を除去します。別プロセスのiframe等を解決できない場合は理由を表示して選び直します。

単体検証は `node --test frontend_ide/checks/browser-element*.test.mjs`。実Chromium検証は `node frontend_ide/scripts/check-browser-element.mjs` で、隔離ページにおけるホバー、機密除外、クリック抑止、内容表示、Esc・遷移・切断を確認し、`frontend_ide/temp/browser-element-check/` に画像を保存します。外部サイトや実AIは使いません。環境がChromiumのソケットを禁止する場合は実画面未実施として扱ってください。説明枠の狭幅・ページ側CSS / CSPとの組合せ、F11、実Electronの連携子窓の位置・前後関係、OSごとのキー入力、Code / Live実窓の下書き保持は別途確認が必要です。子窓と背景の維持は `checks/browser-draft-window.test.mjs`、説明枠の表示・解除は `checks/browser-element-tooltip.test.mjs` でも確認します。

全画面の上端ホバーパネルは単独BrowserとIDE所属Browserで共用します。幅は800 DIPを上限とし、狭い画面では既存の左右余白内へ収めます。rendererは固定幅を重ねずnative窓の100%に合わせます。高倍率などで640 CSS px以下になるとタイトル・接続操作・窓操作を別行へ折り返し、ResizeObserverで増えた高さをnative窓へ返します。背景は不透明度10%の淡いシアン、文字は青系で、OSのacrylic/vibrancyや面全体のぼかしは使いません。配色・操作は後述の「Browserの日本語URL表示」に集約します。手動のWeb画面撮影と下書きへの連携は独立した機能として維持します。移動位置はパネルを表示している間だけ維持し、一度収納したら次の表示は現在の画面上端中央へ戻します。F11で入り直した時も同じ位置へ戻します。通常窓の復帰位置やWeb本文のスクロールは変更しません。mainの状態スナップショットには取得順の `stateRevision` を付け、Vueは古い操作応答・通知を無視します。全画面終了の通知を遅い応答で上書きすると通常の操作欄が隠れるため、この順序判定を外さないでください。`checks/browser-fullscreen-state.test.mjs`、`checks/browser-header-style.test.mjs`、`checks/browser-integration-regressions.test.mjs` で遅延応答・F11連打・ヘッダー読込中の終了・移動位置を確認します。ネイティブの透過合成と実際のキー操作は実機で別途確認します。

BrowserはIDEの `active && mode==='online' && connected` を起動前・非同期準備後に照合します。tools切断時は既存ページを保持したまま非表示にして操作を停止し、再接続時に戻します。接続判定の取得元は既存のIDE接続状態です。Electronのファイル選択では `previewFile()` で実パスとプロジェクト境界を確認し、`pathToFileURL()` による絶対パスのfile URLをBrowserへ渡します。アドレス欄・履歴・MCPのURLもfile URLです。日本語・空白・`#`・`%`を含む名前を手動連結せず、相対画像・CSS・リンクはファイル位置を基準に読み込みます。Browserのfile要求とMCPの遷移先はプロジェクト内の実ファイルに限定します。通常Web起動と既存の「表示」プレビューは `/api/preview` の専用配信URLを引き続き使います。外部ページはpreloadなし・Nodeなし・sandbox有効の別WebContentsで、IDEのAPIオリジンへの要求は拒否します。

IDE配下のMCP sessionはBrowser窓ごとの `aidiy_ide N` です。`backend_tools/temp/_ide_browser_sessions/` の排他的な登録で全IDEから見た最小の空き正整数を確保し、窓の終了で解放します。1・2・3から2を閉じて追加すれば2を再利用します。`record.slot=N-1` とタイトル **AiDiy IDE / Browser N** を同じ番号へ揃え、別の表示用番号を採番しません。Codeの番号はIDEごとですが、MCP session名は全IDE共通なのでBrowserの採番だけはIDEをまたいで一意にします。起動元・作業セッション・寿命はCodeと同様に `record.owner` / `linkKey` で管理し、IDEの利用終了・所有IDE終了では所属Browser全窓を回収します。MCPの `close_session` / `delete_session` は指定したBrowserだけを閉じ、他BrowserやIDEプロセスを終了しません。

単独Browserは起動ごとの固定UUIDを持つ `aidiy_browser <UUID>` で、タイトルは番号・UUIDなしの **AiDiy Browser** です。同じ起動プロセス内で窓を増やしてもUUIDは変更せず、最終窓の終了で登録と中継を解除します。単独版の `close_session` はその起動のBrowser全窓を閉じ、別起動・IDE・通常Chromeは対象にしません。session表示と下書き連携には両方式とも実際の空白付き名をそのまま使います。

登録にはloopbackポート・ランダムトークン・PIDを保存し、`tools_proc/ide_browser_session.py` がChromeレジストリへ接続専用sessionとして組み込みます。トークンやポートは画面へ公開しません。未起動・不正な予約名を通常Chromeや `default` へ退避させず、接続失敗として扱います。旧形式名の稼働中プロセスへの互換接続は維持します。

Vueの通常タイトル・F11上端ヘッダーは `window.aidiyWindow.title()` の限定IPCから同じOSタイトルを取得します。ページ題名・フォーカス中の別窓から組み立てません。取得失敗や不正値では従来の種別名を表示し、破棄後に届いた応答は捨てます。`panel-window-title` の既存の縮小・省略規則を再利用し、全画面パネルの半透明背景は維持します。

Electron全体のremote-debugging-portは使わず、専用ページのCDPだけを中継します。HTTP・WebSocketはloopbackとトークンで限定し、WebページからのOrigin付き要求を拒否します。IDE本体やCode/ConsoleのTargetへアクセスするBrowser/Targetドメインは転送しません。`new_tab` だけは専用アダプターから新しいBrowserパネルを要求します。IDE版では同じ所有IDEに別の `aidiy_ide N` を作り、応答の `session` と `id` を組にして以後の操作へ渡します。新tabを元sessionへ登録した扱いにしません。単独版では同じ起動UUIDのsessionへ追加します。Web起動の通常タブは登録しません。

確認は `node --test frontend_ide/checks/browser*.test.mjs frontend_ide/checks/standalone-browser-desktop.test.mjs` と `backend_tools/.venv/Scripts/python.exe -m unittest discover -s frontend_ide/checks -p 'test_browser_*.py'`。番号の同時確保・閉鎖後再利用、IDE所属と利用終了、new_tab応答session、close_sessionの対象分離、単独UUIDの維持、通常/F11タイトルの一致・失敗・破棄後応答も対象にします。実画面確認は共通Vueの配布物生成と変更済みtoolsの起動後、`node frontend_ide/scripts/check-browser.mjs` を実行します。Googleへの実接続、HTML/HTMと相対CSS・リンク、履歴、MCPからの一覧・クリック・入力・移動・撮影・新規パネル・終了、各ディスプレイのVR起動配置、利用終了連携を確認し、`temp/browser-check/` に画像と結果を保存します。テスト用プロジェクトとElectronプロファイルを使い、有料AIや音声は起動しません。

## 起動メニューとバーガー・＋の図形

IDE上部の起動ボタン列は `src/components/共通表示/起動メニュー.vue` が描きます。Electron版（別ウィンドウを開く）とWeb版（パネルを開く）は `App.vue` の `desktopLaunchItems` / `panelLaunchItems` を渡し、項目は Console → Navigator → Code → Live → Browser → TASK → TEAM の順です。項目名に「＋」は付けません（Navigatorの `navigation-launch` クラスと、起動中の「起動中…」表示は維持）。窓幅が `max-width:900px` 以下（`breakpoint`）のときは、枠付きの「＋」だけを表示し、押すと下向きの起動メニュー（`.launch-popup`）を開きます。Esc・外側のクリック・項目の選択で閉じます。広いときは、枠付きの「＋」の右に項目を横に並べます。VRの起動メニュー（`.all-launchers`）も項目名から「＋」を外しています。

バーガーと「＋」は、角を丸めない枠（`--burger-size` 22px、太さ `--burger-line`）の中に、2本線（バーガー）または十字（`.plus-mark`）を描く同じ部品です。frontend_webのハンバーガー（2本線）と同じ構成で、角だけ丸めません。横2本がエクスプローラー、縦2本が軌跡バーで、IDE内・別窓（エクスプローラー、軌跡バー）・VRで同じ `.burger` を使います。ボタン自体の枠は外し（`.burger-button`）、枠は図形側の1本だけにします。線の太さと間隔は `main.js` が表示倍率の整数画素にそろえます。

Navigatorのタイトル行は、左に状況表示と「CODE」ボタン（単独・IDE別窓とも `connection-tools` の差し込み口）、中央にタイトル、右に窓操作を置きます。ボタンの表示は、Codeを開いていないときは「CODE」、開いているときは「CODE非表示」です。タイトルは左右の内容幅によらず窓の中央に置き、狭いときだけ省略します（`grid-template-columns:minmax(auto,1fr) minmax(0,auto) minmax(auto,1fr)`）。Navigatorの初期サイズは幅480・高さ800のままです。

## VRボタンの表示と切り替え

Windowsのフレームレス窓には細いOS外枠が残るため、`全画面横断.cjs` はVR中だけディスプレイ全体の外接矩形より各辺2 DIP外側まで窓を広げます。上端の灰色ラインを画面外へ出し、DPIの丸めも吸収します。メニュー位置は拡張後の実際の窓座標から計算し、VR解除では保存した位置・寸法へ復帰します。通常窓の端ドラッグによるリサイズを維持するため、`thickFrame:false` は設定しません。表示設定変更のたびに画面配置から計算し直し、余白を累積させません。

拡大率の違う画面への復帰では、最初の座標設定が旧DPIで換算されることがあります。大きな寸法差は端数補正へ加算せず、移動先で保存寸法を再適用します。125%などの端数DPIでは、1 DIP小さく指定しても実寸が変わらない場合があります。端数の補正は元の目標値から毎回作り直さず、直前の指定値へ残差を加えて実寸を再確認します。最大4回で制限し、同じ指定値への再訪は打ち切り、一致不能なら最も近かった指定値へ戻します。

環境変数 `AIDIY_ALL_EDGE_ONLY=1` を設定して `node frontend_ide/scripts/check-all-displays.mjs` を実行すると、実Electronの画面外への枠配置・VRの5往復・通常窓の復帰位置と寸法の完全一致を検証し、上端画像と `temp/all-displays-check/edge-result.json` を保存します。Electronが`host/node_modules`にある環境では、`ELECTRON_PATH`に`frontend_ide/host/node_modules/electron/dist/electron.exe`の絶対パスを指定します。検証窓はGPU負荷を避けるためソフトウェア描画、窓座標とDPIは実OSです。確認後は環境変数を解除してください。手動相当の再確認ではIDEを再起動してから復帰ボタンとF11の両方を試し、移行前後のキャプチャ寸法・原点も比較します。実施記録は[IDE操作編](../../docs/セルフテスト、操作ガイド/セルフテスト,aidiy_ide,操作編.md)を参照してください。

`App.vue` の `canEnterAll` は、Electron版・利用開始済み・3D表示の3条件で判定します。起動画面、2D表示、`--browser` のWeb版ではVRボタンを表示しません。切り替え処理の入口と準備完了後でも同じ条件を確認し、VRから戻す操作は許可します。

表示条件だけを確認する場合は、環境変数 `AIDIY_ALL_BUTTONS_ONLY=1` を設定して `node frontend_ide/scripts/check-all-displays.mjs` を実行し、実行後に変数を解除します。この確認は隔離Electronをソフトウェア描画で動かし、起動画面・3D・2Dの撮影と、Electronのpreloadを持たないWeb画面の非表示を確認します。VRの画面横断・復帰サイズの検証は、変数を設定しない通常の同スクリプトで別途行います。

VRへの移行ではExplorerと軌跡を順に自動ピン留めします。ファイルビューアーとソース比較は自動で別窓にせず、中心星の右128pxから、最大幅640px・高さ720pxのIDE内パネルに表示します。表示領域より大きい場合は縮めます。ファイル選択のたびにIDE内の閲覧を差し替え、選択やパネル開閉で宇宙の中心を補正しません。明示的な📌でだけ別窓化し、既にピン留めした同じファイルはその窓へフォーカスします。

Explorerと軌跡のVR位置は `デスクトップ/VRパネル配置.cjs` がIDE本体ごとにメモリー内で保持します。VR終了時、親窓を通常サイズへ戻す前に両別窓のDIP座標を記憶します。次回はピン留め・VR展開後、Web側の元表示の消去描画を待ってから、Explorer→軌跡の順に各650msで前回位置へ移動し、その間は共通の四方向マーカーと「VR空間へ移行中…」を表示します。初回・同位置では移動演出を省略します。移動先を示す操作のため、装飾のアニメーション抑制とは独立して移動とマーカーを表示します。サイズは保存せず現在の寸法を保ち、画面構成変更時は作業領域へ収めます。移行中断時は通過点を保存せず、タイマーとマーカーを解除します。永続設定には書き込まず、IDE終了で忘れます。検証は `node --test frontend_ide/checks/vr-panel-placement.test.mjs frontend_ide/checks/all-displays.test.mjs frontend_ide/checks/code-drag.test.mjs`、実窓は `AIDIY_ALL_PANEL_POSITION_ONLY=1` を指定して `node frontend_ide/scripts/check-all-displays.mjs` を実行します。実窓を移動してVRを3回往復し、位置復元・移動中のマーカー・寸法維持を確認、`temp/all-displays-check/panel-position-result.json` と画像へ保存します。

VR中は再オープン用の入口が隠れるため、Explorerの別窓タイトルの×と内部の閉じる☰、軌跡バーの×を非表示にします。VR解除では両方の別窓を閉じ、本体でも非表示にします。DOM・閲覧履歴・検索状態は保持し、通常画面の「☰」「軌跡」から再表示できます。`ファイル一覧.vue` でVR状態の解除を監視し、既存のdismiss処理でDOMを回収してから閉じます。ビューアーなど他の別窓はそのまま維持します。

VR中の復帰・起動メニューは全ディスプレイの作業領域の右上に置き、マウスオーバーまたはキーボードフォーカスで表示します。復帰マークの下のConsoleはその画面の左下、Codeは右上、Liveは左上へ開きます。Liveは接続利用中かつ未起動の場合だけ表示し、終了後はメニューへ入る時の状態取得でも再表示します。`全画面横断.cjs` の `toolbars` は画面IDとIDE内の割合座標を返し、`openApp` は任意座標ではなく画面IDだけを渡します。main側でVR状態・実在画面・所有元を照合し、起動準備中の切断やVR解除も窓生成時に再確認します。通常起動の配置と窓番号は維持し、VRの重ね位置だけ画面別に数えます。

環境変数 `AIDIY_ALL_LAUNCHERS_ONLY=1` で同スクリプトを実行すると、接続中の各実ディスプレイでホバー表示・3種の起動位置・Liveボタンの非表示/復帰・各画面からのVR解除を検証し、メニュー画像を保存します。IDE画面・IPC・別窓・表示演出は実Electronで、接続状態と子窓の本文サーバーをfixtureに替えます。Code CLI・PTY・マイク・有料APIの検証は含みません。

この閲覧動作は環境変数 `AIDIY_ALL_VIEWER_ONLY=1` を設定して同じスクリプトで確認できます。実ElectronのVR中で、移行前の比較DOM保持・中心右の配置・連続選択で窓が増えないこと・手動ピン留め・VR解除後の閲覧保持と、Explorer・軌跡の閉じる操作の非表示、解除時の別窓終了・通常画面からの再表示・VR再移行後の再終了を検証し、`temp/all-displays-check/` に画像を保存します。窓の復帰寸法は通常の全体検証で確認し、この限定検証の合格で代替しません。

## Code / Live の操作・遅延応答を確認するとき

## HTML / SVG の相対参照を確認するとき

`ファイルビューア.vue` のHTML/SVG表示は `/api/preview` が返す別ポートのURLをiframeで開きます。`viewer/preview.mjs` はプロジェクト内のフォルダ構造をURLに保持し、同じフォルダ・親フォルダの画像、CSS、モジュールを通常のブラウザと同じ相対URL解決で配信します。SVGを `/api/raw` のimgタグへ戻すとSVG内部の外部画像が読めなくなるため、文書として表示してください。SVGは表示を既定とし、コードへの切替も提供します。

プレビューのiframeと文書CSPには `allow-same-origin` を付け、外部SVGのuse参照などを可能にします。IDE自身とは別ポートで隔離し、元のプロジェクト外や設定・鍵ファイルの配信拒否を維持します。ディレクトリのindex.htmlは末尾スラッシュ付きURLへ誘導し、画像の基準位置をずらさないでください。ファイル切替・破棄では古いプレビューAPIの応答を無効化します。

文書と資産の `Referrer-Policy` は `same-origin` とし、外部画像などへtokenとプロジェクト内パスを送らないでください。同一プレビュー内ではRefererを維持し、`/…` 始まりの資産をページの `public` 基準で解決します。参照元の公開元も、このプレビューのローカルまたは確認済み転送先に限定します。

Codespacesの転送先からAPIを開いた場合は、既存の `forwardedOrigin()` でプレビュー用ポートのHTTPS URLを返します。IDEとプレビューは別の転送公開元を維持し、IDEと同一公開元へHTMLを中継しないでください。Hostを書き換える転送では既知のOrigin / Refererも判定に使います。ローカルから開いた場合はループバックURLを返します。初回起動でtokenを含まないローカルURLを出力し、Codespacesのポート検出へ通知します。自動転送されない場合はPortsからそのプレビューポートをPrivateのまま転送し、必要なら転送先を別タブで一度開いて認証してから再読込します。ポートをPublicへ変更する必要はありません。

`node --test frontend_ide/viewer/checks/preview.test.mjs` と `node frontend_ide/scripts/check-preview.mjs` で配信・ブラウザ表示を確認します。前者は転送HostとプロキシがHostを書き換えた場合、ローカル利用、token・パス・別サイトの拒否も確認します。後者は別ポートの模擬外部画像にRefererが送られず、ルート相対画像は読めることも確認します。実Codespacesのポート転送・認証確認はローカルのHost模擬テストとは別に実施してください。実ファイルは `check-preview.mjs --project <ルート> --html <相対パス> --svg <相対パス>` で読み取り専用に検証し、`nn-preview-*.png` に撮影します。配信側を変更した際は、画面再読み込みだけでなくIDEを終了して再起動してください。

プロジェクトバーの「Tools接続確認」はCodeの `auto-connect` トグルを共用します。既定ON、WebSocketの `tools-check` で切り替え、`tools` 応答の `enabled` / `online` で画面を同期します。OFFは疎通の定期実行を止め、シアン表示を解除して赤いバーにします。ONへ戻すと即時に疎通確認を再開します。シェルの再起動は行わず、端末の再起動でも同じサーバー内の選択を維持します。確認中にOFFへ変わった場合の古い応答は世代番号で無視してください。

キー変換は `src/components/コンソール/キー入力.js` に集約します。Ctrl+C / Cmd+C はコピー、Ctrl+V / Cmd+V はxterm標準の貼り付けに任せ、それ以外の修飾キーを送信します。Ctrl+英字・記号は通常の制御文字、Windows / LinuxのAlt+文字はESC付き、標準の制御文字がない組合せはCSI-uで送ります。MacのOption / Shift+Optionによる通常文字はxterm既定の `macOptionIsMeta:false` に合わせて文字入力へ委ね、ESCを付けません。OS判定はサーバー側ではなく入力元ブラウザーの `navigator.platform` を使います。Ctrl・Alt付きのTab、修飾Enter、修飾Insert / PageUp / PageDownも送信し、ブラウザー操作やxtermのローカルスクロールに使いません。日本語配列の記号はkeyCodeのUS配列換算ではなく `event.key` を使います。IME変換中・AltGraph・Deadキーはxtermへ委ね、keydownだけで送信してkeypress / keyupの重複を防ぎます。受信側CLIの対応によって解釈は異なります。`node --test frontend_ide/checks/console-keyboard.test.mjs frontend_ide/checks/console-size.test.mjs` と `node frontend_ide/scripts/check-console-keyboard.mjs` で、英字・記号・複合修飾、コピー、日本語の通常貼り付けとbracketed paste、IME、二重送信を確認します。実ブラウザー検証は専用プロファイルと模擬WebSocketを使い、コマンドを実行しません。


修飾Enterは接続先の入力形式を優先します。WindowsのCodexはWin32の入力レコードを読むため、CSI-uの文字列だけではShift / Ctrlを伝えられない場合があります。xtermの公開parserでConPTYの `CSI ? 9001 h/l` を監視し、有効な間だけShift / Ctrl / Alt+Enterの全組合せを `CSI Vk;Sc;Uc;Kd;Cs;Rc _` へ変換します。EnterはVk=13、Sc=28、UcはCtrl付きならLF=10、それ以外はCR=13です。修飾はShift=16・Ctrl=8・Alt=2、テンキーEnterはさらに256です。UcをCRへ固定すると、Node/libuv等の文字ストリーム入力でCtrl+Enterが通常Enterへ化けるため、修飾ビットと文字値の両方を保持します。Alt+EnterはCRとAltビットを送り、文字入力側でESC+CRへ変換されます。keydownごとに押下・解放を一組で送り、フォーカス移動時のkeyup欠落と二重送信を避けます。これは修飾Enterの補完であり、全キーのWin32入力実装ではありません。

ブラウザーのOSやCLI名で形式を固定しないでください。要求がない端末では従来のCSI-u / ESC+CRを保ち、通常Enter・IME・Meta・コピー・貼付けは変更しません。parserハンドラーはfalseを返して同じCSI内のカーソル・bracketed paste等をxtermへ渡します。表示クリアでは入力モードを保持し、再接続・RIS（`ESC c`）では解除、破棄時は購読を解放します。再接続では旧接続の追加出力を捨て、xtermに残る未解析出力を空writeの完了で排出してからリセット・新PTYの開始を行います。`terminal.reset()`だけでは未解析の9001要求が後から復活するため、連続再接続と破棄の確認も必要です。CLI再接続は同じPTYを保つため、サーバーの `input-mode.mjs` でもモードを出力履歴とは別に保存し、末尾256KiBの履歴を再生した後に `keyboard-mode` 通知で復元します。起動時の9001要求が履歴から消えても維持します。Kitty / modifyOtherKeysの完全対応を宣言する応答は追加しません。

修飾Enterの確認は `node --test frontend_ide/checks/console-keyboard.test.mjs frontend_ide/checks/console-size.test.mjs frontend_ide/checks/console-enter-pty.test.mjs`。実xtermの分割・複合CSI解析、既存モードの保持、再接続・破棄、Unix実PTYのバイト列を確認します。Windowsでは同じPTYテストがPowerShellの `Console.ReadKey` でEnter・全7組の修飾・KeyChar（Ctrl付きLF／それ以外CR）を確認し、他OSではこの1件をskipします。`node frontend_ide/scripts/check-console-keyboard.mjs` は現行Vueソースを一時コンパイルし、隔離Chromiumと模擬WebSocketでブラウザー入力・クリア・再起動を検証して撮影します。`--compile-only` はブラウザーを起動しません。Windowsの実Codexで改行・通常Enter送信・日本語IMEを確認する試験と、WSL / SSH先でのConPTY変換確認は別途必要です。

Win32のCtrl+Enterと、拡張プロトコルの独立したCtrl+Enterは、文字入力のCLIでは同じ動作になるとは限りません。Claude CodeではLF（Ctrl+J）とAlt+Enterは改行ですが、CSI-u等で区別されたCtrl+Enterはv2.1.275以降、既定で `chat:sendNow`（即時送信）です。Console側で全形式を改行へ置き換えたり、Claudeのキー設定を変更したりしません。CLIの版・キー設定・Windowsの入力方式を確認し、転送したバイトの正しさと実CLIの動作確認を分けてください。Windows実機での未実施試験を、Linuxの単体・ブラウザー試験で合格扱いにしません。

入力形式の参照先: [Microsoft ConPTY仕様](https://github.com/microsoft/terminal/blob/main/doc/specs/%234999%20-%20Improved%20keyboard%20handling%20in%20Conpty.md)、[Microsoft Return文字変換](https://github.com/microsoft/terminal/blob/main/src/terminal/input/terminalInput.cpp)、[libuv Windows文字入力](https://github.com/libuv/libuv/blob/v1.x/src/win/tty.c)、[Codex Windows入力モード](https://github.com/openai/codex/blob/main/codex-rs/tui/src/tui/windows_console.rs)、[Claudeキー設定](https://code.claude.com/docs/en/keybindings)、[Claude端末設定](https://code.claude.com/docs/en/terminal-config)。

フォーカス境界の単体・実Vue setup検証は `node --test checks/console-focus.test.mjs checks/console-size.test.mjs checks/console-window-title.test.mjs`。`node scripts/check-console-focus.mjs --compile-only` は配布用buildなしでVue・xterm・scoped CSSをコンパイルします。`node scripts/check-console-focus.mjs` は隔離Chromiumと模擬WebSocketで、余白クリック直後の日本語入力・再復帰・ボタン・選択保持・タブ・再起動・破棄を確認して `temp/console-focus-check/` に撮影します。実行にはChromiumのローカルソケット権限が必要です。この試験の窓focus通知は模擬のため、実Windows/macOSの非アクティブ窓のクリック、Alt+Tab、最小化からの復元、IMEの変換途中の復帰は別途実機で確認してください。

## 状態確認・最終更新・下書き連携の境界

- `宇宙描画.js` の一覧更新では、選択ファイルとビューアを途中の欠落で解除しません。取得結果に選択パスがなければ `fresh=1` でもう一度走査し、その結果をまとめて反映します。フォルダ監視の欠落も同じ全体走査へ回し、確認中の新しい選択・手動解除を優先します。通信失敗と、現在フォルダを含まない打ち切り結果では元の表示を保持します。自動追跡も移動先の確認前には前のビューアを閉じません。`checks/space-mode.test.mjs` と `navigation-parity.test.mjs` で一時欠落・削除・確認中の操作・取得失敗・走査上限を確認します。
- `App.vue` と `閲覧ウィンドウ.vue` は `src/components/共通表示/接続状態.js` で利用状態の応答を検証します。HTTP失敗・タイムアウト・不完全なJSONを `active:false` に置き換えないでください。Appの状態取得と下書き連携の確認には開始時のrevision・セッションを照合し、終了や再開後の遅延応答を捨てます。Electron側の `デスクトップ/desktop-session.cjs` も同じ方針で、子窓監視失敗では破棄せず、終了確認時の不明は確認が必要な作業中として扱います。
- `ファイル一覧.vue` の最終更新通知は、一覧の鮮度更新と自動追跡を分けます。初回表示の候補だけツリーから用意し、以後のツリー書換えでは `latest` を通知しません。新しい最終更新は `/api/latest` から検知して通知します。同じ更新の再取得では通知を重ねません。`宇宙描画.js` の手動latest/未知パス移動は `fresh=1` で再走査し、新しい手動選択・clear・フィルター切替・破棄があれば中断します。進行中の走査を共有した結果が古い場合だけもう一度確認します。自動探索のON/OFFで手動クリックを無効にしないでください。
- `ファイルビューア.vue` は `ファイル参照.js` でgrepの行・列・検索語を現在の内容と照合します。Monacoと簡易表示の双方に位置を伝え、CRLF/CR/LFとUTF-16列を扱います。本文変更や削除で不一致なら再検索の案内にします。
- `下書き連携ダイアログ.vue` は初回表示時に候補を取得し、有効な `frontmostTargetId` を初期選択します。閉じて再表示した時も、その時点の最前面を取り直します。連携先行の「最前面を再選択」は候補を取り直し、`frontmostTargetId` を選び直します。通常の候補更新では有効な手動選択を保持し、再選択だけで下書きを追加しません。有効な候補が1件なら最前面情報の有無によらず名前を表示して選択します。最小化・非表示などで最前面情報がない場合は「最前面は未確認」と明示し、最前面と断定しません。初回表示・再選択時に複数候補の最前面を特定できなければ未選択として案内し、一覧での明示選択を残します。ゼロ件で自動起動・自動送信はしません。`コードパネル.vue` / `ライブパネル.vue` の `draftTarget()` / `insertDraft()` は `src/components/下書き連携/下書き受け渡し.js` を共有し、今の下書きに追記します。Codeは合計200,000文字、Liveは20,000文字、選択本文は80,000文字までで、超過は切り詰めず拒否します。Codeの新規・履歴切替など会話変更操作では、要求を送る前に連携先を同期的に無効化します。途中の旧会話stateやHTTP成功だけで復帰させず、要求先の会話stateまたは変更前の確定拒否を待ちます。VS CodeはrequestId付きのconversationChangeResultと会話stateを照合し、実行中・モデル変更中・消えた履歴の拒否でも安全に復帰します。マルチルートの新規だけは、ホストが成功応答で確認した別の作業フォルダへ移れます。履歴選択は要求した会話ID・元のプロジェクトを維持します。応答喪失や500は適用済みか判断できないので、旧下書きのまま連携を停止し再読み込みを案内します。`checks/code-transition-handoff.test.mjs` は実テンプレートのクリックとHTTP/SSE・VS Code経路を検証します。
- Webは `連携先登録.js` のマウント固有IDと会話contextIdを再照合します。ピン留めはAppが実際に開いたWindow参照だけを登録し、同じ公開元・IDEセッション・プロジェクトと送信元の生存を確認します。BroadcastChannelやlocalStorageに本文を流さないでください。
- Electronは `デスクトップ/draft-router.cjs` が所有IDE、セッション、窓ID、会話contextId、プロジェクトを検証し、限定したpreloadのIPCへ渡します。受信結果のACKまで待ち、期限切れ・閉じた窓・再配送を扱います。表示名やCodeの配置番号だけで相手を決めないでください。最前面候補はホストのウィンドウfocus順を記録し、現在の所有IDE・セッション・登録に一致する表示中のCode / Liveだけから選びます。IDE・ビューア・ダイアログへのフォーカスや登録情報の更新では順番を変えず、閉鎖・最小化・非表示の窓は最前面候補から除外します。Webは最後に表示したCode / Live種別をマウント固有IDへ変換し、Console・ダイアログを候補にせず、利用再開時に記録を消します。
- LiveのWebパネルは隠してもマウントを保持し、`visible` でマイク取得待ちを無効化し音声入出力を止めます。会話・下書き・スピーカーの選択を残し、再表示でマイクを自動再開しません。

`viewer/file-scan.mjs` の走査は同じサーバー内でフィルターと走査範囲（通常/grep）ごとに1秒だけ共有し、同時実行は1本です。grepのbackup除外は走査前に行い、対象外の保存版で候補・フォルダ・深さ・時間上限を消費しないようにします。通常のgalaxy/latestとは進行中の要求・キャッシュを分離し、通常一覧のbackup表示条件は維持します。明示操作の `fresh=1` は完了済みキャッシュを使わず、進行中の同じ走査は共有します。既定上限は30,000ファイル（backupフィルターは100,000）、10,000フォルダ、200,000項目、128階層、10秒。待機者の個別中断、全待機者の中断、利用終了・切替、サーバー終了を伝播し、中断した走査はキャッシュに残しません。常時watcherは使いません。

`/api/galaxy` は従来のtreeに走査件数・時間・打切り理由を加え、`/api/latest` は同じ情報をscanにも持ちます。`/api/grep` はpathsを維持し、matchesにpath/line/column/length/snippet/mtime/sizeを追加します。grepは1ファイル1MB、合計256MB、候補30,000ファイル、一致1,000件、30秒、最大8並列読み取りです。読み取り中にファイルが変わったらスキップします。UIはtruncatedとtruncationReasonを捨てないでください。

## 3D / 2D の表示部品を変更するとき

- `App.vue` は利用セッションごとの `viewMode` を持ち、開始時は3Dにします。プロジェクト名の直後に3D / 2D、右側にConsole / Code / Liveを配置します。表示モードを `SpaceView` やCode / Live / Consoleのkeyに含めないでください。
- `開発スペース.vue` は共通の走査結果・選択・エクスプローラー・読み取り専用ビューアを結びます。`宇宙キャンバス.vue` は既存の `createSpace()` を包む薄いライフサイクル部品です。3Dエンジン内の既存の走査・選択・移動管理を共用し、二重取得や別セッションを作りません。
- 3Dは現在フォルダの直下ファイルを惑星、直下サブフォルダを銀河にし、各銀河の全子孫ファイルを1ファイル＝1星で描きます。深いフォルダによる集約・間引きは行いません。空フォルダは個別のファイル星を持たず、直下に来た時は空の銀河として移動できます。星の座標は銀河内の相対パスで区別し、色・容量によるサイズ・更新や検索の強調もファイル単位で保ちます。クリック・検索・履歴・最終更新は実ファイルの親へ移動します。銀河の更新件数は走査・マーク変更時に集計し、毎フレームの描画やhoverで元ツリーを再走査しないでください。新規星の誕生時刻と描画時刻はどちらも実時刻を使い、通常サイズの4倍から6秒で元へ戻します。`checks/star-depth.test.mjs` で集約前の座標・色・サイズ・瞬き、同名ファイルの区別、12,000件の深いファイルの個別描画・当たり判定、検索・航路・追加削除・6秒の新規強調を確認します。非表示時の描画停止・ラベル幅キャッシュ・通信周期の負荷改善は維持してください。
- `setViewMode('2d')` はRAFとワープの待機・アニメーションを中断し、3Dのキー・ポインター操作を止めます。2Dの最終更新追跡は、共有の自動探索ON/OFF・手動操作後の猶予・手動プレビュー保護を守るイベント駆動です。探索枠の回転条件も3Dと共通にし、更新候補がない待機中も自動探索が可能なら回します。手動猶予の終了時だけ1回起きて枠を復帰し、更新予約があれば追跡します。OFF・モード変更・フィルター・セッション・非表示・破棄で古い処理を無効にし、常時のRAF・追加ポーリングは作りません。`goTo` / `ascend` / ブラウザ履歴は2D中だけ直接階層を切り替えます。3Dへ戻す時は同じworldと現在の選択を保ち、描画予約を必ず1本だけ再開してください。ページ非表示からの復帰でも2DのRAFを再開しません。
- `フォルダページ.vue` は初めて2Dを選んだ時に生成し、その後は部品の記憶を保持します。非表示中は全ツリーの集計や項目DOMを作りません。`フォルダページ構成.js` が直下項目と更新・検索一致数を集計し、ページごとのスクロール・選択行を記憶します。本文や認証情報は保存しません。新しい走査・検索マークで、ユーザーが矢印キーで移したカーソルを開いているファイルへ巻き戻さないでください。
- 2Dページだけは本文18px・行高1.5、補足16px（行内のサイズ・日時・件数は行高1.125）を使い、共通の `--file-font-size` やCode / Liveの文字設定は変えません。固定insetの `.folder-pages` をsize containerにし、幅520px以下では補足を次行へ、高さ360px以下では見出しと補足欄をコンパクトにします。一覧の最小高さ96pxとページ外側のスクロールを残し、縦表示のプレビュー中に一覧が潰れないようにします。日時・長い名前は省略せず、動作確認では狭幅・長いパンくず・一覧外参照の案内を組み合わせてください。
- 2Dページ切替は旧ページを上に残し、下の移動先を右に傾いた斜線（上端が右の `/`）に合わせて露出させる方式です。進む時は斜線が右→左、戻る時は同じ傾きのまま左→右へ動き、同じ時間・ease-in曲線でゆっくり始めて徐々に加速します。旧ページの `clip-path: polygon()` とSVG線の上下端を `--page-turn-slant`（幅20%・上限160px）で揃え、傾き分だけ画面外まで動かして開始・終了時の四隅に旧ページや移動先の欠片を残さないでください。SVG線は `preserveAspectRatio="none"` と `vector-effect="non-scaling-stroke"` で高さに追従し、線幅2pxを保ちます。`folderPageTurnPlan()` で共通の親への戻りと目的の枝への進行を求め、各経由ページの実データを順に重ねます。1階層でも複数階層でも移動全体を約800msに揃え、実際に表示する枚数で総時間を等分します（1枚800ms、2枚400ms、3枚約267ms、4枚200ms、5枚160ms）。深い経路は共通の親と最終目的地を落とさず最大5枚へまとめ、省略した階層数も表示します。共有の現在地・選択はすぐに最終目的地へ反映し、途中の枚数は視覚効果として扱います。初回表示・モード復帰では再生せず、OSの設定を理由にページ繰りを止めません。同じ階層の更新は下方向の更新演出を使います。実操作する移動先のスクロール領域は階層パス、旧ページ・経由ページ・斜線はめくりごとの一意なIDでkey付けします。表示専用ページはスクロール位置・選択行を保持し、`inert` / `aria-hidden` を付け、optionのIDを複製しません。旧ページのanimationend/cancelが新しいページを止めないよう、イベントの対象・アニメーション名・一意IDを照合してください。完了時は表示用シートだけを外し、操作側のDOMを維持します。途中の一覧クリックや決定キーはまず演出だけを終え、下に隠れた別の項目へ誤操作しないようにします。ホイール・タッチ移動・スクロールバー操作や一覧更新でも演出を解除し、親ボタン・パンくず・外部からの新しい移動は最後の目的地を優先します。ページ演出にタイマーや描画ループは追加せず、CSSのend/cancelと入力・更新通知で後片付けします。背景は `frontend_web/src/assets/menu-common.css` の既存クリーム色（#faf7f2 / #f5f1e8 / #f0ebe0、文字#5a4a3a）を2D専用CSS変数で使い、3Dと共通ビューアの色は変えません。軌跡バーの高さはResizeObserverとresize時だけ測り、狭い画面でパンくずへ重なることを防ぎます。フォルダ移動後は項目リストへフォーカスを戻し、共有ビューアのEscも維持します。矢印/Home/End/PageUp/PageDown、ホイール、タッチ移動、スクロールバー等のポインター入力はactivityから共通エンジンへ手動操作を通知します。scroll自体は位置の保存だけとし、復元・scrollIntoView・検索更新によるプログラムスクロールで手動待機を延長しないでください。

### 自動探索ボタン上の航行状態

自動探索ONの間だけ、ボタンのすぐ上へ現在の状態を表示します。航行状況は枠・背景・影を付けない文字だけにします。2Dでは文字色だけを変えます。`space-flight-controls` は `z-index:5` とし、航行状況・自動探索・高速ワープをビューア（30）とエクスプローラー（40）の背面へ置きます。パネルが重なった部分は隠れ、航行状況は `pointer-events:none` で操作を妨げません。`宇宙描画.js` が実際の処理から `explorationStatus` を通知し、`開発スペース.vue` が表示します。追加のタイマーやポーリングは使わず、状態が変わった時だけ通知します。

| 表示 | その時の動き |
|---|---|
| 出航準備中 | 起動時の読み込み・導入飛行を進めます。 |
| 航路確認中 | 更新先のファイルと経路を確認します。 |
| 目的地へワープ中 | 別の星系へワープします。 |
| 目的地へ接近中 | 同じ星系の目的地へ旋回・前進します。 |
| 手動操縦中 | ドラッグ・ピンチなどの操作を優先します。 |
| 軌道計算と姿勢制御中 | 位置を保ちながら、軌道線の切替・計算・姿勢合わせを進めます。 |
| 探索軌道航行中 | 探索用の軌道に沿って進みます。 |

## 閲覧・検索軌跡の明細と分岐

閲覧の `voyages[階層パス]` は `経路記録.js` の `{ from, to }` 明細を追加順に保存します。点は従来と同じ `g:フォルダパス` / `f:ファイルパス` で識別し、現在点は `voyageCurrent[階層パス]` に分けます。最初の明細の `from: null` は、出発点のない始点レコードを明示したものです。閲覧では従来どおり最初の点だけを描き、中心からの線は追加しません。検索は従来の各階層の入口（中心）を最初の `from` にして一本道を描きます。

既存点へ戻ったら現在点だけを更新し、明細の追加・並べ替え・既存の出発点の書き換えはしません。A→B の後に A を再訪して C へ進む場合は、末尾に A→C を追加します。経路の同一性は向きを区別しません。A→BとB→Aは同じ経路として1明細にまとめ、最初に記録した明細のfrom/toの向きと追加順を保持します。`sameRoute()` / `uniqueRouteRecords()` を閲覧の追加・旧データ復元・検索の明細生成で共有します。旧明細に始点行がなくてもfrom側を既存点として認識し、逆向きの再訪は現在点だけを更新します。点マーカーはfrom/toの両端を対象に重複除外し、逆辺の整理後にfrom側にだけ残る現在点も強調します。各線は明細自身の両端から描き、配列の前後を結び直しません。途中のファイルが削除・非表示になった場合も、その点を飛び越す線を捏造しません。古い点への再訪も判定できるよう、従来の40点での航路切り捨ては行いません。閲覧日時一覧 `journal` は航路とは別用途なので、従来の最近順・最大80件を維持します。

保存はバージョン2の `{ version, voyages, voyageCurrent, journal }` です。旧文字列配列は読み込み時に初訪問の明細へ変換し、再訪は現在点の更新として処理します。旧形式では最後の参照点を現在点にし、新形式では保存された現在点を優先します。壊れた明細だけを除外し、使える他の明細は残します。AI検索結果は従来の `route` パス配列APIを互換維持し、同時に `routeRecords` の `from` / `to` 明細を共通の `searchRouteRecords()` で生成して返却・履歴保存します。点IDは閲覧と同じ `f:ルート相対ファイルパス` で、最初の `from` は `null`、後続は直前の `to` です。入力結果の1MiB上限は維持し、派生明細のパス重複を含む保存履歴だけは読み書き共通の3MiB上限にします。入力で受理した長い500件の結果が保存後に読込不可にならないことと、上限超過の書込が既存履歴を壊さないことを確認してください。検索結果の `files.path` / `route` 自体へ `f:` を付けないでください。旧履歴の読み込み時も検証済みの `route` から明細を補完します。外部結果内の明細は信用せず、順序と全ファイルの一意性を検証した `route` を正として生成します。

FileExplorerは検索明細をrouteイベントの `records` として送り、SpaceView経由でengineが複製して保持します。旧UIの `paths` だけの通知は同じ生成関数で補完し、検索順と矛盾する明細を採用しません。描画境界の `aiRouteRecords()` は保持した論理明細のファイルIDを各表示階層へ投影し、深いファイルをその階層の親フォルダ位置へ写します。この描画座標・親フォルダの点と、保存する `f:パス` の論理明細を混同しないでください。検索の互換用`route`配列とファイル巡回順は維持しますが、投影後の軌跡明細にも向きを区別しない同一路判定を適用し、逆向きの線を重ねて描きません。例えばsrc→other→srcはsrcとotherを結ぶ線1本とし、最後の点の強調は重複除外後の最後の明細ではなく元の検索順のsrcに残します。検索の順序を閲覧の重複除外規則で変更しないでください。

フォルダは親階層の点です。2D / 3Dの `goTo({type:'dir', ...})` は共に `parentOf(path)` の航路へ記録し、そのフォルダ自身の子階層へ混ぜません。ルート移動では空パスの点を追加しません。

## 2Dのフォルダ状態監視・更新表示

2Dの「自動探索」がONで表示中の間、`ファイル閲覧/フォルダ監視.js` が `/api/folder-state?path=<プロジェクト相対フォルダ>&filter=backup` を確認します。画面のフィルターOFFでは `filter=` を渡します。表示は直下だけですが、子フォルダカードの件数が再帰集計なので監視範囲も現在フォルダ以下の再帰です。親や兄弟のフォルダへは広げません。

- 応答は `files`（ファイル数）、`latest`（対象ファイルの最新mtime・Unixミリ秒、空ならnull）、`revision`、`fileList`（プロジェクト相対のpath/name/size/mtime）、`tree`（既存形式）です。一覧・件数・日時・指紋は同じ1回の走査から作ります。`since=revision` が一致すれば `unchanged:true` となり、一覧とツリーを省きます。表示更新は返されたツリーを直接利用し、再取得の全体走査を追加しません。ファイル名の表示順は既存の日本語・数値自然順です。
- 除外規則は従来の `viewer/file-scan.mjs` の値を `backend_server/core_router/フォルダ除外規則.json` に移し共有しています。backupの意味を変更せず、変更が必要なら元の `AIバックアップ.py` と照合してください。指紋は対象パス・サイズ・mtime・ctime・inodeと表示対象ディレクトリ名から作り、ディレクトリmtimeは使いません。対象外ファイルの変更で親mtimeが動いても、再描画しません。本文は読みません。OSのメタデータをすべて維持した特殊な書換えは検知対象外です。
- 通常は応答完了から30秒後に次回を確認します。開始・再開・対象切替時の初回確認と手動更新は即時です。大規模走査・不完全結果・HTTP失敗後も30秒待ちます（フォルダが見つからない場合の既存の10秒再試行は維持）。OFF・3D・非表示・利用終了・フォルダ/フィルター切替で要求をabortし、世代番号でも古い応答を捨てます。サーバーの同時走査は1本で、フィルター・対象フォルダを分けた短期キャッシュを共有します。
- 上限は通常3万/backup10万ファイル、1万フォルダ、20万列挙、深さ128、走査10秒です。`truncated` と `truncationReason` を必ず確認してください。不完全な結果は表示を置き換えず、案内を出して30秒後に再確認します。一覧を返す場合の件数は返した部分一覧と一致します。
- 自動更新は差分がある時だけ、右上の手動更新は成功したら差分がなくても、上から下へ線と旧ページの切り抜きを650msで動かします。移動・連続更新・ユーザー操作では旧演出を取り消し、OSの設定によって演出を省略しません。スクロールと残存する選択を維持します。
- 今日の日付は閲覧端末の年/月/日で判定し「今日 HH:mm」を赤字表示します。それ以外の従来表記と元日時tooltipを維持し、ローカル深夜と再表示時に判定を更新します。無効な日時は「—」です。
- フォルダカードは角丸なし、四辺に沿ったinset shadowで外周を濃くします。名前とメタ情報の列では右側に固定42%を予約せず、メタ情報の内容幅以外を名前に使います。

バックエンド共用APIは認証付き `POST /core/files/フォルダ状態` です。bodyは `{"フォルダ":"src","フィルター":"backup"}`（OFFは空文字）です。サーバー設定のCODE_BASE_PATH内だけを許可し、絶対パス・親脱出・リンク・除外フォルダへの直接指定を拒否します。`data` に `ファイル数`、`最終更新日時`、`ファイル一覧`（パス/名前/サイズ/更新日時）、`変更識別子`、`不完全`、`制限理由` を返します。IDE独立サーバーでは既存のHost/Origin/利用開始とプロジェクトルート境界を使う同等APIを使い、オフライン利用を保ちます。Python側も同じ上限と2秒キャッシュ、同時走査1本を使い、混雑時は429を返します。

## 3分類の軌跡ツリーとフォルダ境界

軌跡バーは「閲覧軌跡」「検索軌跡」「AI検索軌跡」です。起点日時の指定・プリセット操作・grep実行で検索軌跡へ、AI検索開始・再確認・履歴選択でAI検索軌跡へ切り替えます。結果到着だけに依存しません。検索失敗では前回確定した同分類の結果を維持し、空の成功結果は空状態にします。3分類の選択は対応する実際のツリーと描画へ渡し、閲覧記録を追加しません。現行エクスプローラーの非AI検索は時刻検索とgrep検索です。将来別の検索方法を追加する場合も `beginSearch` / `acceptSearch` を同じ経路で使います。

ツリーは `開発スペース/軌跡ツリー.js` の表示用変換です。閲覧は保存済みvoyagesのfrom/to、AIは検証済みrouteRecords（旧結果はrouteから補完）を使います。grep・起点の結果は関係性を持たない並列候補として表示し、ファイルの名前順・フォルダ階層を経路の親子に置き換えません。同一路・逆辺は既存規則でまとめ、循環や合流は参照行で展開を止めます。反復処理なので長い経路にも再帰上限はありません。

フォルダの親階層にある `g:パス` は到着点、そのフォルダ内のnull始点は内部の出発元です。表示だけに `o:パス` を使い「到着 → 出発元」の対として示します。保存形式v2・保存済み明細・現在点・再訪時の重複判定は変更しません。ルートの表示用出発元は `o:` ですが保存する空パスの点は追加しません。＜ ＞はツリーの表示順に辿り、同じフォルダの到着／出発元を1操作へまとめます。通常ファイルは1件ずつ進み、終端で無効になります。各点を直接選ぶ操作も同じgoToへ渡します。

閲覧のクリアはファイル閲覧journalだけを消します。フォルダの記録が残る場合はその部分を表示し、消したファイルを保存済みの辺から復活させません。検索・AI分類と保存済みvoyagesは保持します。表示用変換からlocalStorageを直接書き換えないでください。

## ExplorerとViewerのピン留め・表示開始

Electronのピン留めは、DOM移動前に元パネルの表示範囲を `capturePage` で撮影し、本体の同じ位置に操作不可の画像として残します。比較・Monaco・iframeの実体は従来どおり1つだけ移動します。別窓の表示演出と描画が完了したら元画像を除去し、失敗・終了・親破棄でも必ず片付けます。撮影範囲にはCSS座標へ窓のzoomだけを掛け、OSのDPI倍率は重ねません。展開中の軌跡は窓の初期サイズ用のバー範囲とは別に、元パネル全体を保持します。

Electronは親IDEからの限定IPCで、一度だけ使えるwindow名とabout:blankを予約します。子窓を既存のセッション監視に登録し、利用終了・親終了で閉じます。Webは親のpagehideとコンポーネント破棄時に子窓を閉じます。再pinでリスナーやポーリングを積み重ねません。Viewerとソース比較の別窓Xは、その閲覧セッションを終了します。IDE内への自動復元やファイル削除は行わず、Monacoモデル・要求・タイマー・窓参照を解放します。ファイルを選び直せば新しい閲覧を開始できます。子reloadと起動失敗はXとは区別し、既存セッションを保持します。

両別窓の初期位置は元パネルの矩形を使います。ElectronではgetContentBoundsとworkAreaのDIPへwebContentsのzoomだけを掛け、パネルに対応するディスプレイ内へ収めます。OSのDPI倍率を二重に掛けません。Windowsでは外枠が1～2px丸められる場合があります。ブラウザーでは外枠と表示領域の差から位置を見積もり、screenの利用可能領域へ制限します。配置・寸法の要求はブラウザーやOSに制限されるため完全一致は保証できず、複数画面やブラウザーズームでも厳密に配置する必要がある場合はElectronを使います。追加の画面アクセス権限は要求しません。

## 各モジュールの長押し窓移動

全Electronアプリの必須方針と表示開始ズームは [共通,Electronウィンドウ基本方針.md](./共通,Electronウィンドウ基本方針.md) を参照します。ズームは最終寸法の透明パネルで領域を確保し、内側だけを拡大します。軌跡の別窓も `panel-windows.cjs` の共通ズームへ進み、実ウィンドウの外枠を連続拡大しません。

Diagの通常・ミニ表示、Avatarの全Electronパネル、Discord・Slackも同じ処理を使います。他アプリは `デスクトップ/長押し窓移動.cjs` の `attachNativeWindowMove(window,screen,kind)` をmainの窓生成時に一度取り付けます。許可した種別は `diag` / `avatar` / `discord` / `slack`。窓種別の追加時は外側の長押し判定と内側の `code-drag.cjs` の許可集合を揃え、実際の共有controllerを通す回帰も確認します。mainが所有する窓のrecordを内部で作り、`code-drag.cjs` のDIP差分・サイズ補正・解除処理を共用します。rendererへ窓ID・任意座標・新しいIPCを公開しません。詳細な適用箇所・検証は各アプリの運用ナレッジを参照してください。

Electron の Code / Live / Console / Browser / Viewer と、IDEからピン留めした Explorer / ファイルビューア・ソース比較 / 軌跡バーは、左ボタンを同じ位置で0.5秒静止して押すと窓を移動できます。背景などの移動対象面に適用し、入力欄・ボタン・リンク等の操作部品は除外します（軌跡バーの専用移動面など、明示した対象は例外）。押下・解放のnative入力は直ちに通し、短押しを再送しません。0.5秒の判定中に位置を動かした場合は窓移動を開始せず、通常の文字選択・dragを続けます。最大化・全画面の窓では開始しません。

成立後は標準の移動カーソルと静止した四方向マーカーでドラッグ状態を示します。`デスクトップ/窓移動表示.cjs` が透明なpopoverを最前面に置き、iframe・Monaco・比較の左右どちらでも表示します。回転・拡縮の演出は行いません。単にhtml要素のcursorだけを検査せず、押した位置のヒット要素と移動中の画像を確認してください。解放・Esc・blur・ページ遷移・画面破棄で解除し、移動後も解放をページへ渡して押下状態を片付け、成立したgestureのclickだけを抑止して誤操作を防ぎます。

`デスクトップ/長押し窓移動.cjs` が Electron の `before-mouse-event` で入力を調停します。IDE本体・通常の窓・ピン留め窓に加え、BrowserのWebContentsView本文にも取り付けます。Monaco、同一・別オリジンのHTML iframeを共通処理でき、外部ページへIPC権限を渡しません。`preload.cjs` の `nativeWindowMove` がある場合、`src/components/共通表示/長押し窓移動.js` の旧renderer方式を停止して二重処理を防ぎます。Web / VS Codeには導入しません。

IDE本体は通常モードでは窓移動、VR中では中心点移動に分岐します。VR状態はmainで判定し、窓の位置・寸法を変更せず、`development:space-center-move` で開始・開始時からの差分・終了を通知します。差分はDIPから開始時のzoomFactorでCSS座標へ変換し、同じ四方向マーカーをマウスに追従させます。`開発スペース.vue` が手動補正を保持し、`宇宙描画.js` はVR中だけ自動補正・ワープ中の固定中心・補間より手動中心を優先します。短押しと0.5秒前の通常旋回は維持し、長押し後の解放・Escを宇宙の選択や戻る操作へ流しません。VR終了で通常の配置に戻り、同じ開発スペースでVRへ再移行すると補正値を再利用します。別パネルはVR中も窓移動です。

IDE本体の確認は `$env:AIDIY_ALL_CENTER_ONLY='1'; node scripts/check-all-displays.mjs`。実OS窓のVR固定、通常時の位置移動、倍率1.5での差分、複数回の長押し、マーカー追従、解放・Esc・blur、短い旋回を検査し、`temp/all-displays-check/center-result.json` とマーカー画像へ保存します。カーソル位置・フォーカス判定だけを模擬し、Electron入力とVue・宇宙描画・窓座標は実物を使います。

ネイティブ側 `デスクトップ/code-drag.cjs` は窓の種別・信頼した主frame・tokenを検証します。`development:window-move-*` は各モジュール自身の窓、またはIDE本人から名前で指定した所有パネルだけを対象にします。ピン留めパネルは表示済み・同じ所有元・同じ起動世代を `panel-windows.cjs` で照合します。rendererから座標や任意の窓IDを受け取らず、Electronのカーソル・窓位置を同じDIP座標で差分計算します。lease・navigation・終了時にtokenと購読を破棄します。旧 `development:code-move-*` は互換入口として残します。

検証は `node --test checks/native-window-move.test.mjs checks/code-drag.test.mjs checks/code-window-title.test.mjs`。実Electronでは `node scripts/check-module-move.mjs` がCode / Live / Consoleの単独・IDE起動と独立Viewer、`node scripts/check-panel-desktop.mjs` がExplorer項目・Viewer・比較・同一/別オリジンHTML・軌跡ボタン、`node scripts/check-browser.mjs` がGoogle入力欄・HTMLリンク・VR中の各画面を確認します。入力はElectronのsendInputEvent、窓の座標・寸法は実OSを使い、カーソル位置とフォーカス判定だけを模擬します。長押し後の誤クリック防止、短押しの入力・遷移、サイズ維持を検査します。`node scripts/check-code-drag.mjs` は旧renderer方式の隔離Chromeテストとして残します。

## 小さな軌跡パネル

折り畳み時の操作は分類・ルート・前後・ピン・閉じるを1行に収めます。`route-controls` は折り返さない横並びとし、本体内も別窓も幅360pxを基準にします。本体の `--route-width` を画面幅の割合に戻すと広い画面で間延びするため、固定幅を維持し、狭い画面では画面内へ制限します。通常幅360pxでは横スクロールも出しません。Electronの移動ハンドルも同じ行に置き、タイトル専用の行を増やさないでください。画面下端の検証は固定の本文高ではなく、バーを含めた下端が画面内に収まることを確認します。

本体内・別窓の軌跡バーは幅360px・高さ40pxを基本とし、ボタン間隔0px、左右余白3px、バーガー幅26px、分類文字10pxに揃えます。分類のボタンは余白へ引き伸ばさず、同じ文字幅・パディングを使います。別窓側だけを小さくするCSSを追加しないでください。狭いWeb画面では従来の画面幅制限と横スクロールを維持します。`checks/panel-desktop-probe.cjs` はバーを開いてからピン留めし、透明領域内のズーム完了後に1行・横スクロールなしを確認します。高さが異なるバーガーボタンとの整列は縦中心で比較し、Chromiumの矩形計算には0.01pxの誤差を許容します。軌跡だけを調べる場合は `AIDIY_PANEL_ROUTES_ONLY=1` で同じ実Electron検証を実行できます。

ExplorerとViewer／比較のElectron別窓は、既存の `閲覧ウィンドウ.vue` と同じ `共通表示/状態バー.vue` を `ファイル閲覧/別窓タイトル.js` から表示します。OS標準枠を重ねず、接続状態は親IDEの状態バーへ追従します。窓操作は `development:panel-action` を使い、所有元・窓名・起動世代・許可操作を検証して子窓だけに適用します。親の `window.aidiyWindow.close()` を直接呼ばないでください。reload／復帰時はタイトル用Vueと監視を破棄し、検索・閲覧のDOMは従来どおり保持します。

軌跡バーの📌は閲覧・検索・AI検索の3分類とツリーを同じDOMのまま別窓へ移します。閉じた状態では幅360px・バーの実測高だけの小さなパネルとして開きます。分類を開くと上端を保ったまま下へ最大300px伸ばし、260msの展開が終わってから本文を表示・操作可能にします。閉じる時は本文をすぐ隠し、縮む演出の後に窓の領域をバーの高さへ戻します。

別窓の最前面ピン・×は `別窓タイトル.js` でバーの末尾にこの順で追加します。×は独立窓を閉じ、本体内に同じ軌跡バーを開いたまま戻します。分類の前へ挿入しないでください。Explorer・軌跡を別起動している間、本体側に開き直すバーガーを残しません。×で本体へ復帰した後は通常の表示に戻します。閲覧軌跡の左の二重縦線は削除し、左端のバーガーだけを `-webkit-app-region:drag` の即時移動面にします。独立窓ではクリックで閉じず、タイトルバーの代わりに使います。VR / ALL表示でも左端の縦三本を非表示にせず、最前面ピンの固定とは独立した移動面として残します。分類・ピンは静止0.5秒の長押し移動に対応し、短押しは従来の操作、移動成立後の解放はクリックを抑止します。本体内のバーガーは折り畳み操作を維持します。入力欄・開いたポップアップの保護も維持します。実窓で左端から即時移動できることと、分類ボタン・ピンの長押し移動後に分類・ピン状態が変わらないことを確認します。

エクスプローラーの見出し用のflex・最小幅は `header>span` の直接の子だけに適用します。`header span` ではバーガー内部のspanにも最小幅が付き、26pxのボタンから三本線がはみ出して見出し文字へ重なります。本体の時刻・grep・AI検索と別窓で、三本線がボタン内に収まり、見出しと交差しないことを `checks/panel-desktop-probe.cjs` で確認します。

`src/components/ファイル閲覧/軌跡パネル展開.js` がWeb埋込・別窓共通の開閉状態を持ちます。世代番号とタイマー解除で途中反転、連打、遅れて届く領域確保応答を処理し、分類だけの変更では再展開しません。Document移動・reloadでタイマーとresize/reduced-motion購読を付け直し、破棄時に解除します。画面下端では表示可能な高さに収め、reduced-motionでは高さ演出を省略します。

Electronは枠なし・透明の軌跡専用窓を作り、`development:resize-routes` で透明な領域を先に確保してから共通の高さ演出を開始します。IPCは信頼済みIDEとその所有する軌跡子窓、同じ起動世代に限定します。手動リサイズを無効にするのは[Electronの透明窓の制約](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)によるものです。実OSでの透明表示・プログラムによるサイズ変更は、モック検証とは別に確認してください。

Web別窓はOS背景の透明化を保証できず、ブラウザーが最小窓サイズやresize要求を制限する場合があります。先にresizeを要求し、取得できた内側の高さに表示を収めます。Web埋込でも同じ下方向の演出を使います。Electronの透明な余白はクリック透過にはしません。

右端の×で独立窓を閉じると、本体内に軌跡バーを開いたまま戻します。独立窓のバーガーは即時移動専用です。OSの閉じる操作では、本体でバーを折り畳んで「軌跡」ボタンを残します。記録・分類を保持し、再表示後も選択ジャンプ・閲覧軌跡のクリアができます。reloadは閉じる操作と区別して同じDOMを再接続します。表示に失敗した場合は本体側を保持します。

検証は `node --test checks/route-expansion.test.mjs checks/navigation-parity.test.mjs checks/panel-windows.test.mjs checks/panel-lifecycle.test.mjs`、ビルド後に `node scripts/check-route-expansion.mjs`。後者は隔離Chromeと一時プロジェクトで開閉中の高さ・本文の表示時刻、途中反転、画面下端、reduced-motion、3分類・実ツリー・ジャンプ・X復帰・クリア・親終了を確認します。AI検索は固定結果に置き換え、外部AIの実行を禁止します。Electron実窓の検証とは区別してください。

## 横画面のビューアとVR操作領域の余白

## VR中のExplorer・軌跡バーの重なり順

`デスクトップ/VRパネル前面.cjs` はVR中だけ、所属する独立窓のExplorer・軌跡バーをIDE本体の直前へ配置します。画面は別rendererでも、BrowserWindowは同じElectron mainの `windows` で管理されるため、新しいプロセス間通信やOS親子関係は不要です。独立起動した別IDEやConsole / Code / Liveなどの選択順は変更しません。

全窓のピン層は引き続き `floating` です。Windowsでは上位層名だけに頼らず、[ElectronのmoveAbove](https://www.electronjs.org/docs/latest/api/browser-window#winmoveabovemediasourceid) と本体の `getMediaSourceId()` で相対Z-orderを指定します。VR切替、表示、復元、本体の選択・最大化関連イベントで補正し、OSイベント完了後に一回だけ再適用します。focus()、blurからの奪い返し、定期タイマーは使用しません。非表示・最小化したパネルを勝手に表示せず、終了時に購読と未実行処理を解除します。通常表示へ戻ると補正を止め、ピンはVR前のユーザー選択へ戻します。

確認は `node --test frontend_ide/checks/vr-panel-stacking.test.mjs frontend_ide/checks/window-pin.test.mjs frontend_ide/checks/panel-windows.test.mjs frontend_ide/checks/all-displays.test.mjs frontend_ide/checks/code-window-title.test.mjs frontend_ide/checks/project-instance.test.mjs frontend_ide/checks/vr-panel-placement.test.mjs`。`checks/vr-panel-stacking-desktop.cjs` は実Electron APIのスモークテストです。headlessでの合格はWindows実デスクトップの重なり順の保証ではありません。

Windows実機では、すでに開いた両パネルでVRへ切り替え、本体を繰り返し選択、最小化・復元、画面構成変更、VR中のパネル再作成、VR解除を確認します。本体への入力が維持され、両パネルが本体に隠れず、通常表示では従来の選択順へ戻ることを撮影して確認してください。OSの保護画面・他アプリの特殊な最前面窓・Waylandの制約まで超える絶対的な最前面保証ではありません。今回の制御は直接読み込むmain側CJSなので、これだけの変更でVue配布bundleを再生成する必要はありません。


### VR中のピンと前面維持の確認

画面内に埋め込まれたExplorer・軌跡・Viewerの📌はOFF表示、切り離した窓はON表示にします。VR中は新しく開いた子窓も共通ピン制御でON固定にし、VR解除後は元の利用者選択へ戻します。

`デスクトップ/VRパネル前面.cjs` は同じIDEに属するピンON子窓を本体より前へ配置します。Windowsでは選択済み本体の再前面化でfocus通知が出ないため、WM_WINDOWPOSCHANGEDも監視し、OS処理後に一度だけ補正します。フォーカス奪取、OS親子化、上位topmost層、周期的な再固定は使いません。

確認では本体を続けて2回選ぶ操作、別アプリへの切替、VR開始後のViewer・Code・Live・Console追加を含めます。`checks/vr-panel-stacking-desktop.cjs` を実Electronで起動し、WindowsのZ順とWS_EX_TOPMOSTを照合します。headlessのAPI成功だけで前面維持の合格にしません。全画面では本体をずらして裏を探せないため、パネルが見え続け、直接選択・移動できることを実画面でも確認します。

## 控えめなパネル外周

Electron・Web・VS Code の共通画面はタイトル背景と同じグレー `#30343a` の1px外周を表示します。共通の `共通表示/タイトルバー配色.css` にある `--aidiy-panel-border` がタイトル背景トークンを参照し、Task / Team・Diag・Discordも同じ外枠色へ揃えます。`src/style.css` の`border-box` で外寸を変えず内側に1pxを確保し、操作やスクロールバーへ装飾を重ねません。固定ヘッダーとCanvasもその内側に合わせます。Web内の子パネルは既存の1px境界の色だけを変更し、Code / Live / Console自身へ枠を重ねません。Browser全画面の繰り出しパネルは通常外枠の対象から明示的に除外し、専用のすりガラスの縁だけを表示します。透明な軌跡窓とVR全面には画面全体の四角枠を追加せず、実パネルの境界を使います。検証は `node --test checks/panel-perimeter.test.mjs`。実機のElectron境界や倍率別の描画は別途目視確認してください。

## BrowserのAI解析とIDEソース選択

`ファイル機能/browser-analysis.mjs` が `GET /api/browser-analysis?url=...` と `POST /api/browser-analysis`（`{url,title}`）を所有します。Browser単独ではこのAPIと接続状態だけを公開し、一般のファイルAPI・Console起動は公開しません。実行時はTools接続と現在の利用セッションを確認します。

解析依頼にはプロジェクトの `base_name` / `base_path` と、Electron本文から取得したURL・タイトルを渡します。概要と関連ソースを同時に調べ、結果は `{requestId,url,summary,files:[{role,path,summary}]}`。実在するプロジェクト内ファイル、相対パス、認証・除外フォルダ、リンク先を検証してから保存します。未確定URL・秘密値を含むURLは受け付けず、URL・ページ文言・ソース内の指示は調査データとして扱います。

`ブラウザ解析ダイアログ.vue` が結果を一覧表示します。`デスクトップ/ブラウザ解析連携.cjs` はソースクリック時に保存済み結果ID・一覧所属・現在URL・起動元IDEセッションを再確認し、IDEへ通知します。`開発スペース.vue` は通知を既存 `selectExplorer` へ渡し、ファイルビューアで開きます。単独起動ではソースクリックを無効にします。解析画面は `デスクトップ/ブラウザ解析窓.cjs` が管理するBrowserの子ウィンドウで開き、native本文と全画面ヘッダーの表示・寸法を変えません。連続操作は同じ解析窓を前面に戻し、開いた時点の解析対象を保持します。親窓の終了・読込失敗で子窓とIPC権限を片付けます。解析窓のIPCは対象取得・閉鎖・関連ソース選択だけを許可します。通常のCode / Live連携と要素連携も `デスクトップ/ブラウザ補助窓.cjs` の専用子窓を使い、背景のWeb本文を表示したまま宛先を選びます。

再検証は `checks/browser-analysis.test.mjs`、`checks/browser-analysis-source.test.mjs`、`checks/browser-analysis-ui.test.mjs`、`checks/browser-analysis-window.test.mjs` と既存 `checks/browser-*.test.mjs`。画面ハーネス `scripts/check-browser-analysis.mjs` は実Vueと模擬APIを使い、`--compile-only` なら配布ビルドやブラウザーを起動しません。実AIや実Electronでの動作確認とは区別してください。

## Browserの日本語URL表示

「Code / Liveへ」は、実際の `session` と送信元の `tab_id` を先頭に付け、表示中URLを同じプロジェクトの下書きへ追加します。IDE配下はBrowser窓ごとの `aidiy_ide N` と同じNのタイトル、単独Browserは起動中固定の `aidiy_browser <UUID>` とタイトル `AiDiy Browser` を使います。空白を含むsession名をそのままMCPへ渡します。単独版の複数窓とIDE番号再利用後の誤操作を避けるため、`tab_id` も併記します。名前の割当とtab IDは `ブラウザCDP.cjs` が所有し、下書きはフォーカス中の窓ではなく送信元レコードから作成します。撮影後60秒以内だけ、画像の絶対パスも添えます。`デスクトップ/ブラウザ.cjs` が撮影時刻と直近画像を保持し、追加直前にも再判定します。単独Code／Liveと別IDEの候補は `デスクトップ/下書き共有.cjs` のloopback・トークン付き共有口から探し、実際の配送と受信ACKは既存の `draft-router.cjs` を使います。別プロジェクト・古い会話へ渡さず、AIの送信ボタンは自動で押しません。下書き連携はBrowserを親とする専用子窓で開き、WebContentsViewは表示・寸法を維持します。F11の操作ヘッダーだけは子窓表示中に収納します。同じ種類の連携を連続操作した場合は同じ子窓を前面へ戻し、要素連携から通常の「Code / Liveへ」へ切り替えた場合は内容を流用せず子窓を作り直します。ページ遷移・再読込・切断・最小化・親窓終了では子窓を閉じます。追加時にも現在のページ・セッション・選択IDを照合し、古い対象を転送しません。専用試験・画面・PDFは[Browser操作編](../../docs/セルフテスト、操作ガイド/セルフテスト,aidiy_browser,操作編.md)を参照してください。同書のBR-404にある本文を隠す動作は旧版の実機確認結果で、現在の子窓表示の確認結果とは区別します。

Browserの接続表示の右には「撮影」を置きます。表示中のWebContentsViewだけを`capturePage()`でPNG化し、選択プロジェクトの`temp/input/browser-<UUID>.png`へ保存します。タイトルバー・URL欄・デスクトップ全体・スクロール外のページは含めません。任意の保存パスはrendererから受け取らず、撮影中の連打・切断・ページ遷移は拒否します。保存後は画面に保存先を示します。Avatarの`input_image`はAIコアの`backend_server/temp/input`への保存とLive送信であり、このBrowserのプロジェクト内保存とは別の経路です。Browserの撮影だけではLiveやAI推論を起動しません。

Browserのタイトルバーの「FHD」はWeb本文の表示領域を1920×945、「縦表示」は1080×1785にします。`デスクトップ/ブラウザ表示領域.cjs` が実測した操作欄・CSS外周枠・OS枠を加えて外窓を拡大します。画面の作業領域より大きくても本文を縮めません。画面内に収まる場合は中央、収まらない場合は操作欄の左上を作業領域内に置いて右・下へはみ出します。macOSではBrowserだけ `enableLargerThanScreen` を有効にします。本文のzoomはプリセット時に1へ戻し、OSのDPR・UA・タッチは変更しません。スマホエミュレーションの機能ではありません。

「F11」ボタンとF11キーは現在のディスプレイのネイティブ全画面表示を切り替え、本文は実際のcontent領域いっぱいになります。全画面中は最前面を維持し、通常のヘッダー・外周枠を隠します。「🔲」は最大化／通常復帰です。F11、🔲、手動リサイズではプリセットの固定を解除し、その時の本文領域に追従します。プリセットへ切り替える際は非同期の全画面解除・最大化解除完了を待ち、後から押した操作を優先します。

全画面専用パネルは `デスクトップ/ブラウザ全画面パネル.cjs` が透明な子BrowserWindowとして管理し、同じVueの `#browser-header` を読みます。上端4pxへのマウスオーバーで約0.22秒かけて展開します。不透明度10%（透過率90%）の淡いシアン背景で、幅800 DIPの透明なガラス面として表示します。中央のWeb本文が実際に透けるよう、OSのacrylic/vibrancyと面全体のぼかしは使いません。ボタン・URL欄も淡い下地にし、4辺は入力を遮らない疑似要素で少し濃い縁と明るい反射線を重ねます。文字は控えめな青系（#4b8eaa）にし、文字や操作部全体のopacityは下げません。WebContentsViewは全画面の同じ矩形を維持し、パネルを重ねても本文を縮めません。専用パネルの📌は表示の継続です。オンで常時表示、オフで即収納し、マウスが離れてから次の上端オーバーで再表示します。背景・タイトルの0.5秒長押しは共通の `長押し窓移動.cjs` を使い、移動開始時に自動で常時表示をオンにします。位置の固定ではなく、オンのまま何度でも移動できます。通常時の📌（窓の最前面維持）とは状態を分けます。

## Navigator の変更・確認

開発目標のNavigationは `src/components/開発スペース/Navigationパネル.vue`、APIと結果検証は `ファイル機能/navigation.mjs` が所有します。IDEの起動欄で「Console」の手前にある「Navigator」から、独立した作業窓を追加します。Explorerのバーガーや上下分割とは連動しません。既存の `createPanelWindow` を使い、Electronでは独立窓、Webではポップアップで開きます。複数窓は起動順のID（navi-1等）ごとに目標・結果・評価・モデル・実行状態を分離します。VRでは既存の独立窓の配置・ピン動作に従い、移行/復帰で窓を増やさず、入力と結果を保持します。パネル表示だけではAIを実行しません。

「ナビ」「再評価」の明示操作、または自動航行でCodeが成功した後の再評価で、`navigation_readonly.py` から既存CodeAgentsの選択済みモデルを使い、`AI実行オプション.読取専用予測()` を固定して目標とプロジェクト調査を依頼します。通常HTTP runや変更可能な経路へフォールバックしません。モデルには読取専用ツール境界が適用され、会話継続・履歴保存・出力ファイル保存は無効です。読取専用に未対応の設定では失敗として表示します。実作業の開始ではありません。Toolsのオンライン表示に関係なく、ローカル実行依存が利用できれば送信できます（後述の実行経路を参照）。依頼ID・目標・最大50項目・一意ID・整数0〜100の達成度・根拠・次のプロンプト案を検証し、成功結果を `_AIDIY/aidiy_navi/navigation/<プロジェクト実パスのSHA-256>/<窓ID>/latest.json` に原子的に保存します。AIはJSONを返答するだけで、アプリが検証後に専用状態へ保存します。対象プロジェクトに結果ファイルを作成しません。達成度はAI推定であり、人による検証済みの意味ではありません。無効な結果・期限切れ・利用セッション変更を成功扱いせず、前回の正常結果を維持します。表示はテキスト補間に限定し、AIのHTMLやコードを実行しません。

Codex / Copilot / Hermesは共通の通常システム指示を使い、Navi固有の制限文を追加しません。読み取り専用の強制は実行オプションと各方式の制限に任せます。WindowsのCodexではMXC優先を使い、専用ファイルの読取と作成拒否を確認しました。MXC非対応環境は別途検証が必要です。

ナビ・再評価の処理中は前回の明細・総合評価・おすすめを隠し、AiDiyアイコンと「FINDING YOUR ROUTE」を表示します。成功時は新しい結果、失敗時は前回の正常結果とエラーを表示します。開始画面と探索中のアイコンは、マウスが左側に入ると右へ、右側なら左へ、回転する四角と共に表示範囲の端まで移動します。同じ側の端にいるときは反対側へ移ります。タッチでは動かず、他画面の開始アイコンには適用しません。

Navigationはパネル表示・VR移行だけではAIを呼びません。「Navigator」の明示操作で初回分析を開始します。既定指示を入力欄へ実値として表示し、その指示でナビを押した場合は既存のファイル走査・除外規則から最近のファイル相対パスと更新日時（最大30件）を取得し、関連内容を読んだうえで仮目標を推測します。走査が上限に達した場合はその制約もAIへ伝えます。更新日時だけで達成を断定させず、推定目標と未確認部分を画面へ明記します。目標は利用者が編集できます。

「評価」は保存済みの目標と項目を対象にします。項目ID・名前・順序・数を変えた回答は拒否し、達成率・根拠・次のプロンプト案だけを更新します。入力欄の目標変更を項目に反映する場合は「Navigator」を使います。ナビ・再評価だけではプロンプト案を送信しません。明示的に「自動航行」をオンにした場合は、後述の専用Codeによる実行と読取専用再評価を繰り返します。


モデル選択は左側カラムの入力説明の下から行い、初期値は `aidiy_hermes` とCode共通の `CODE_AIDIY_HERMES_MODEL`（省略時auto）です。読取専用対応の `aidiy_hermes` / `codex_cli` / `copilot_cli` / `claude_cli` / `grok_cli`、`same` / `auto` または設定済みのモデル名を選択します。Code本体の選択値を上書きせず、`_AIDIY/aidiy_navi/aidiy_navi_model.json` へ、画面で確定した最後の選択を保存します。形式・検証→専用一時JSON→原子的rename・ファイルmode 0600はCodeの `aidiy_code_model.json` と同じです。プロジェクト・窓に共通の1ファイルで、Code・Liveの保存ファイルは変更しません。新しく開く窓はこの値で始まります。開いている窓どうしは共有せず、各窓は最初に読んだ値か自分で確定した値を保持して、他の窓の確定では変わりません（開いた時点で保存値がなければ既定値のまま、保存ファイルを再読込しません）。旧形式の窓別 `model.json` は読みません。成功結果と履歴は従来どおり窓・プロジェクトごとに復元します。ナビ・評価の開始時に選択を固定します。実行中のモデル保存は拒否します。Hermesは既存読取専用アダプターのツール許可リスト、Codex/Copilotは既存の各CLI制約を再利用します。Claude CLIは `--restricted` / `--safe-mode` / `--strict-mcp-config` と読み取りツールのみの `--tools` を使います。Grok CLIは `--tools read_file,grep,list_dir` とMCP・委譲の除外、`--sandbox read-only` を使います。CLIが引数を受け付けなければ失敗します。CLIの管理者設定やGrokのユーザー設定のフックはCLIの仕様に従います。Grokのsandboxは環境によって適用されない場合があり、WindowsでOSレベルの書込禁止を保証するものではありません。未対応の実行方式へ自動フォールバックしません。通常ランタイムの認証・診断キャッシュまで禁止するOS全体の隔離とは区別してください。

Navigationの外枠はCodeと同じ状態バー・窓操作とプロジェクト表示を使います。入力説明の下のモデルボタンは共通ダイアログを開き、Diagが生成するread-only専用の `navi_models_info.json` に含まれるコードAI、same/auto、モデル候補、任意のモデルIDを選択します。Diagの書出し時に未導入のCLIとHermesの実行環境がない方式を除き、読取専用非対応のHermes外部CLI候補も除外します。選択肢はCodeの合成一覧と同じ順序で、保存済み一覧を使い、導入状態をリアルタイムに再判定しません。認証・利用枠は一覧だけでは確認できません。許可するAI方式は既存read-only対応の5方式に限定し、選択を他のNaviやCodeへ反映しません。


### Navigatorの単独起動と履歴

初期サイズは `host/scripts/window-size.cjs` の幅480・ナビ高さ900を使います。Code / Liveの会話高さ600とは分けます。単独・IDE・VRは `windowBounds('navi', area)` で小画面の作業領域へ縮小し、Webパネルも高さ900を上限に、上部バーと下端16pxの余白を除く表示領域へ収めます。初期寸法だけを変更し、手動サイズ、Codeオン／オフの別々のサイズ保持、VR復帰時の既存窓の寸法は上書きしません。`checks/navigation-size.test.cjs`、`checks/panel-windows.test.mjs`、`checks/navigation-code-window.test.cjs`、`checks/navigation-popup-size.test.mjs` で確認します。

- `aidiy_navi [作業フォルダ | --project 作業フォルダ]` はCode同様に起動フォルダを対象にする。`--browser`、`--new-window`、`--foreground`、`--port` を共通起動処理で扱う。モデルは画面から選び、起動引数で上書きしない。
- IDEのアプリ選択（別窓・パネル・VRの3か所）は `Console`、`Navigator`、`Code` … の順。Navigatorも他のアプリと同じく、押すと `launching==="navigation"` で全ボタンを無効にして「起動中…」を出し、`Navigationパネル.vue` が窓を開き終えて `opened` を出すと解除する（`closed`、または10秒で解除）。順序と表示は `checks/folder-pages.test.mjs` が確認する。
- 単独タイトルは `AiDiy Navigator`。IDEの「Navigator」からの窓は `AiDiy IDE / Navigator 1` のように実際の起動番号を表示する。
- 「＋ 新規」は現在窓の選択を解除する。「一覧」で同一プロジェクトの過去ナビを選ぶと目標・項目・評価を復元する。モデルは今の選択を保ち、履歴に残っていたモデルへ切り替えず `aidiy_navi_model.json` も更新しない（Codeの履歴選択も同じで、会話本文だけを開く）。評価は元の項目構成を保持し、そのナビの履歴を更新する。選択と一覧閲覧ではAIを呼ばない。

### Navigator の実行経路と Tools 稼働状態

Navigator は `navigation-agent.mjs` からセットアップ済み `backend_tools/.venv` の Python を起動し、`navigation_readonly.py` が `CodeAgents.run_async` と既存 Code CLI 基盤を読み取り専用オプションで呼びます。常駐 Tools（8095）の HTTP/MCP API や独立した `aidiy_code_agent` コマンドは呼びません。Tools サーバーの起動状態でナビ・評価を無効化せず、Python・選択した CLI・認証・モデルが利用できない場合は実行エラーとして表示します。通常実行へのフォールバックは行いません。

Navigator の戻り値は `schemaVersion:3, requestId, goal, items[{id,name,progress,reason,weight,weightReason}], overall:{progress,reason}, nextItemId, nextPrompt` の固定JSONです。`progress` は0〜100の整数、未実施・未評価・根拠不足は0%として理由に明記し、保存済み記録のnullは受け付けません。今回のAI応答に限り、明示的な未評価nullを0%へ数値化し、総合がnullならAIの工数比率と数値化後の全項目から加重値を算出して検証します。欠損フィールド・文字列・不正な比率や数値の不一致は成功にしません。項目は最大50件、IDは重複不可です。各項目の全体工数比率 `weight` は1〜100の整数で合計100%。総合は全項目の `sum(weight*progress)/100` を四捨五入した整数で、項目がない場合は0%です。工数比率・配分理由と総合値・根拠はAIが返し、APIが検証します。画面側で別の平均値を作りません。旧形式やnullを含む保存済み記録は補完・自動移行せず、「＋ 新規」から作り直します。再評価時は保存済みの目標・項目ID・名前・順序・件数・根拠reason・工数比率weight・配分理由weightReasonを照合し、変更を拒否します。明細はprogressの数値だけを更新します。総合値は固定した工数比率で検証し、最新の根拠はoverall.reasonとnextPromptに記載します。再評価の未評価nullを0%へ数値化するときも、保存済みの明細根拠には加筆しません。パース・検証に成功するまで前回の正常結果を置き換えません。AI検索の結果ファイル検証と同様に構造を検証しますが、読み取り専用を守るためAIにプロジェクト内のJSON作成を依頼せず、アプリが専用状態領域へ保存します。

Navigatorの依存可否は `navigationAvailability` でローカルPython・CLIのみ確認します。起動・履歴読戻しを拒否せず、実行APIとボタンで判定し、画面は5秒ごとに再確認します。認証や利用枠を探る自動AI送信は行いません。

Navigatorの新規ナビ作成では空入力をUI・APIの両方で拒否し、AIを呼びません。再評価は保存済み結果がある場合だけ利用でき、目標欄が編集済み・空欄でも押せます。押下時にそのナビの最終実行時の目標へ復元し、APIも保存済み目標を使います。実行失敗では前回の正常結果を保持し、押下後に新たに入力した下書きは完了時に上書きしません。「＋ 新規」は既定指示へ戻し、履歴選択は保存済み目標へ戻します。Code共通の開始表示部品にnavi用の英文を渡し、帯なしAiDiy画像を使います。タイトル行はCodeと同じ31px・14px文字、本文は黒、外枠はタイトル色1pxです。単独の接続表示は既存createCoreConnectionのTools ping、IDE別窓は所有IDEの接続バーに同期します。ナビ／評価の処理中はCodeのprompt-reflect演出を共有し、接続状態の表示とは分けます。


### 独立アプリ追加時のConsoleとの照合

Navigator等の追加時は、起動入口・setup/cleanupの表示と登録順・setup/startの停止所属判定・共有依存使用中保護・Diagカタログ/アイコン配布・IDE起動導線・タイトル/サイズ・長押し移動のmain/renderer両側・ピン/VR・履歴/モデル保存・文書索引を確認する。旧アプリ一覧を固定したテストfixtureも更新する。
NavigatorはConsoleのPTY、シェル自動承認、CLI補完、端末入力中継を使用しない。全体startの自動起動一覧へ追加せず、手動で開く。Diag診断の過去インベントリや過去試験結果を、現在の追加機能の実機確認済みとして書き換えない。



Navigatorの入力欄は「目標」と表示します。総合評価は明細のスクロール外に置き、パネル下部の「おすすめプロンプト(案)」の上へ固定します。長い総合根拠と次のプロンプトは各領域内でスクロールし、履歴一覧や新規状態では結果の下部欄を隠します。`checks/navigation-layout.test.mjs` でVueのコンパイル、下部欄の配置と数値のアクセシビリティ属性を確認します。実画面では縮小窓、長文、明細スクロール、履歴への往復、新規作成を確認してください。

総合評価と明細は共通のコンパクトな進捗行を使い、行内の余白は上下6px・左右10px、明細の間隔は4pxとします。総合評価の外側の上下余白は5pxです。理由と工数比率の開閉は維持します。

明細と総合評価の理由は初期状態で折りたたみます。各タイトルの▶を押すと▽に切り替わり、その項目の達成度の理由・工数比率と配分理由、または総合評価の理由を表示します。HTMLのdetails/summaryを使用し、キーボードでも個別に開閉できます。目標名・達成率は閉じていても表示し、他項目の開閉には影響させません。別のナビ記録へ切り替えたときは初期状態へ戻します。

数値評価の境界は `validateNavigationResponse`（今回のAI応答）と `validateNavigation`（厳密検証・保存済み読戻し）を分けます。旧履歴の自動補完はしません。通信失敗や不正JSONは失敗として表示し、前回の正常な数値結果を保持します。初回失敗時に0%の成功結果を作りません。画面も旧APIや不正応答のnull・欠損を検知し、数値のない成功表示にせず更新と再作成を案内します。

NavigatorはまずAIの返答全体をJSONとして解析します。前後に説明文やコードフェンスが付いた場合だけ、最初の `{` から最後の `}` までを単一JSONとして解析します。文字列内の括弧・引用符・エスケープはJSON構文に従い、複数オブジェクトから任意の1件を選びません。配列・文字列のJSONを勝手に内側の結果へ変換せず、従来のschema・依頼ID・目標・項目・工数比率・総合値の検証を通った結果だけを保存します。不正・曖昧な返答は失敗として前回の正常結果を維持します。

「おすすめプロンプト(案)」の本文は、AI自身が「今回の目標」「対処しようとしている内容」「今回の作業」の流れで、目標の意図・対象項目の残る課題と根拠・具体的な作業と確認方法を含む依頼文として作成します。画面とコピーは保存済みの `nextPrompt` をそのまま使い、目標や項目名を機械的に付加しません。入力欄の編集中の目標に置き換えず、履歴を選ぶとその記録の本文へ切り替えます。「評価」では最新の根拠から依頼文も書き直します。既存の保存済み本文を表示時に補完・再生成しません。コピーは表示中の窓のClipboard APIを使い、API未提供・拒否時は同じdocumentの一時textareaと従来のcopyコマンドを試します。一時要素を片付け、元のフォーカス・選択を戻します。両方式が失敗した場合はボタンの近くに本文選択と手動コピーの方法を表示し、成功扱いにしません。固定の注意書きは表示しません。

おすすめプロンプトは一覧の上から最初の達成率100%未満の項目1つだけを対象にします。schemaVersion 3の `nextItemId` をAIが返し、APIと画面で対象IDを照合します。「評価」で達成率が変わった場合は新しい値から対象を選び直します。未評価0%の項目も順番に含めます。全項目100%・項目なしでは `nextItemId:null, nextPrompt:""` とし、追加作業を生成せずコピーも表示しません。全体目標は背景説明として含め、作業の依頼は対象1項目に限定します。対象IDのない旧記録は推測補完せず再作成します。ID・順序・達成率の整合性は検証できますが、自由文が意味的に対象以外の作業を含まないことの完全な機械判定はしません。

おすすめプロンプトの見出し右は、内蔵Codeの表示中は「CODEへ」となり、このNavigator専用Codeの入力欄へ直接追記します。既存の下書き受信APIで同じプロジェクト・会話・入力上限を確認し、編集中の本文を残してフォーカスします。自動航行中・ナビ実行中・準備中・受信不可では無効にし、外部Code / Liveへ自動で切り替えません。単独Web版も内蔵Codeへの転記は利用できます。Codeを非表示にすると従来の「CODE/LIVEへ」に戻り、他のファイル操作と同じ下書き連携ダイアログを開きます。AI生成本文をそのまま、選んだCode / Liveの既存下書きに追記し、自動送信・実行はしません。IDE内とピン留め窓では既存の連携先・利用セッション検証を使い、単独デスクトップNaviではBrowserと同じプロジェクト限定の下書き共有経路を使います。複数候補は共通ダイアログで選択し、起動していなければ案内します。単独Web版は他タブ連携を公開せずボタンを無効にします。全件完了で提案がない場合はボタンを出しません。ダイアログは開いた時点の本文を保持し、目標の結果・プロジェクト・利用世代・内蔵Codeの表示が変われば閉じます。

通常のナビ・再評価ボタンは灰色で、初期値を含む入力あり・未実行または保存済み目標と異なる場合はナビだけ、目標が保存済み結果と同じ場合は再評価だけをCode送信ボタンと同じ青紫にします。空欄では両方灰色です。灰色は無効を意味せず、実行済みナビの再評価は編集済みでも利用できます。

目標入力欄は4行で表示します。ナビボタンはCodeと同じ `sending.png` の手紙アイコンと「ナビ」の文字を表示し、再評価ボタンと同じ40.6px四方の角丸なしにします。左側は読取専用の説明、保存済み目標との差異説明、モデル選択の縦3段、その右側にナビ・再評価を並べ、モデル表示とボタンの下端を揃えます。差異説明は保存済み結果があり入力目標が異なる場合だけ表示し、該当しない場合は行を出しません。ナビの手紙画像は35pxにし、背景付きの文字を画像に重ねて読みやすくします。左側は残り幅に合わせて折り返し、ボタン寸法を縮めません。ナビボタン下と総合評価上の区切線はタイトルバーと同じ色の1pxです。明細・総合評価の枠、目標入力・おすすめ本文の枠も角丸なしです。目標入力とおすすめ本文は黒背景・文字色・枠・余白・行間を共通にし、目標は編集可能、おすすめ本文は閲覧・選択のみのままにします。

CodeとNaviの `sending.png` は `scripts/build.mjs` が `host/media` からビルド後に配布する画像です。Vueテンプレートでは実行時に解決したURLを `:src` へ渡し、静的な `src="/development/sending.png"` を書かないでください。静的srcはViteの画像importに変換され、配布前の絶対パスが解決できずproduction buildに失敗します。画像参照変更時はVueコンパイルに加えて `frontend_ide` の `npm run build` を実行してください。


### Navigator の埋込Codeと自動航行（Navi Cruise）

タイトル部分の「Code オン／オフ」（状況表示の直後に置き、非表示中は「CODE」、表示中は「CODE非表示」と表示します。タイトル文字は左右の内容幅によらず中央に置き、狭いときだけ省略します）はNavigator自身を右へ拡大し、専用Codeを内部に表示します。開くだけでは提案の入力・送信を行いません。自動航行がオフなら、埋込Codeは人間が入力・送信・モデル選択を行う通常のCodeとして使えます。自動航行の完了・停止後も、実行中の停止確認が終われば同じ画面で手動操作へ戻れます。Codeをオフにすると通常幅へ戻します。自動航行をオンにするとCodeを自動で表示します。その後はタイトルのCode切替で手動で隠せます。非表示でも同じCodeの実行・再評価を継続し、再表示すると会話・入力・実行状態を引き継ぎます。非表示中も総合評価の光と「自動航行中」、状態欄の停止ボタンを表示します。Code切替は表示だけを変更し、通常の手動操作中もセッションを破棄しません。最初のCodeオンでは標準幅480pxの2倍（960px）を使い、すでに960px以上なら狭めません。その後は通常表示とCode表示の手動調整した幅・高さを窓ごとに別々に記憶し、切替時に復元します。位置は現在の位置を維持してディスプレイの作業領域へ収め、小さい画面への一時的な縮小では記憶寸法を上書きしません。Code表示で手動指定した幅は960px未満でも次回に復元します。ただしオンにする時点の通常幅が960px以上なら、より小さい記憶幅への復元より現在幅の維持を優先します。この場合もCode側の手動指定は失わず、通常幅を960px未満へ狭めてからオンにすると記憶幅へ戻ります。寸法記憶は既存Code窓と同様に窓を閉じるまでで、再起動後は標準寸法から始めます。VRのパネル移動中は切替を開始せず案内します。最初から最大化・全画面の場合は既存の領域を維持します。通常表示でCodeを開いた後に最大化した場合は、Codeオフで通常寸法へ戻します。Web別窓も同じ寸法記憶を使いますが、窓のリサイズ・移動はブラウザーの許可範囲に従います。通常ブラウザータブとIDE本体の寸法は変更せず、同じパネル内の右列に表示します。

総合評価100%未満で、保存済み目標・有効な提案・評価環境が揃うと「コピー」の隣の「自動航行」をオンにできます。許可は現在の画面内だけに保持し、履歴、再起動、再表示から復元しません。専用Codeで提案本文を実行し、依頼IDに一致する受付・成功通知を確認した後だけ、既存の読取専用経路で再評価します。100%になれば終了します。評価はAIの推定であり、品質保証ではありません。

Codeのモデル・権限・承認方式・検証回数は既存設定を使い、自動承認や権限緩和へ切り替えません。Navigator評価用のAI選択とは別です。「CODEへ」「CODE/LIVEへ」はどちらも下書き追記のみで、送信しません。

自動接続ONのCodeは初回の状態通知で一時的にoffline表示になるため、自動航行はオンライン接続・セッション・プロジェクトの確定を待ってから送信します。この待機中は理由を表示し、オフラインHermesへ自動で切り替えて実行しません。自動送信する提案はCode入力欄にも表示し、受付後に会話へ移します。人間の入力途中の下書きは別に保持します。Codeの受付確認は30秒、受付後の自動航行の完了監視は1時間です。Code CLI側の15分無応答タイムアウトなど、各実行経路の既存制限は変更せず、先に失敗・中断が届いた場合はその時点で停止します。監視期限超過・結果不明時の自動再送は行いません。

自動航行オフ、Navigator全体を閉じる・非表示にする、プロジェクト・会話・利用セッション変更、切断、Code失敗、再評価失敗、結果不明、空または対象不一致の提案で停止します。Code実行中のオフはその依頼IDだけに停止要求を送ります。停止要求は変更済みファイルの取り消しではありません。再評価中のオフは後続のCode実行を禁止します。3回続けて各項目の最高達成率が改善しない場合も停止し、理由を表示します。失敗・中断したCodeは、同じ依頼IDの実終了通知（`settled:true`）と待機状態が確認できれば、パネルを閉じずに「自動航行 オフ」を押して明示再開できます。失敗から自動では再送しません。切断・応答喪失など実終了が未確認の場合はロックを維持するので、実行結果を確認してNavigatorを開き直してください。Codeの表示オン・オフだけでは会話やロックを破棄しません。

終了通知音は backend_tools の `aidiy_notification_sounds` を呼び出して鳴らします（部品側は変更しません）。画面は `POST /api/navigation/sound` に種別名（`注意` / `完了`）だけを送り、IDEサーバー（`ファイル機能/navigation-sound.mjs`）が同名の通知種別・scene `auto` で `PORT_TOOLS` の `/aidiy_notification_sounds/play` を呼びます。部品の定義により 注意=`_sound_SeatBeltSign2fast.mp3`、完了=`_sound_SeatBeltSign1.mp3`（ポーン1回）です。音を区別するために別の意味の種別へ読み替えたり、英語の別名（ok / ng など）を使ったりしません。任意の通知種別・tts・文字列は受け付けません。
受付（202）は再生完了を待たずに返し、Tools未起動・スピーカー無効は無視して画面の処理を止めません。部品は再生が終わるまで返らず、同時に呼ぶと前の音が切れるため、IDEサーバーが受け付けた順に1つずつ鳴らします（待ちは12件まで。超えた分は鳴らしません）。
- 評価が終わるたび（通常の調査・再評価も、自動航行中の再評価も）: 総合評価が100%なら `完了`（ポーン1回）、100%未満なら `注意`。通常の調査・再評価は、実行中を表示していた依頼の完了で鳴らし、失敗も `注意`、利用者の中止では鳴らしません。
- 自動航行が止まったとき: 100%に達して終了する場合は、その回の評価の `完了` だけで終わります（重ねて鳴らしません）。それ以外（オフ・中止・Code失敗・再評価失敗・3回改善なしなど）は `注意` を鳴らします。Navigatorを閉じたときは鳴らしません。
- 例: 100%に達した回は 完了 の1回だけ、3回続けて改善しなかったときは 注意→注意→注意（評価3回）→注意（停止）と続けて鳴ります。自動航行の再評価は `clientRequestId` で区別し、通常側の終了音と二重に鳴らしません。
- 通知音のオン・オフ: モデル表示と同じ行の右側、ナビ・再評価ボタンのすぐ左に「通知音」のトグル（`role="switch"`）を置きます。2行で、上に「通知音」、下にスイッチと「オン」「オフ」の文字を表示します（枠線・背景の箱は付けません）。スイッチは「自動航行」のトグルと同じ配色・形（濃い四角いレールに丸いつまみ、オンは青緑）を70%の大きさ（レール20×10px、つまみ6px）で再現します、スイッチの下端はボタン・モデル行の下端にそろえます（`align-self:end`）。つまみはオンで右、オフで左に寄り、切り替えにアニメーションは使いません（このパネルには `prefers-reduced-motion` を書かない決まりがあるため）。初期値はオンで、設定はその画面の中だけに保持し、保存しません（開き直すとオン）。オフの間は、評価・失敗・自動航行の停止のどの音も `/api/navigation/sound` へ送りません。
- 「自動航行」のトグルは、オン・オフとも白地に黒文字です（ホバーは薄いグレー）。オンは枠線を濃い緑にし、スイッチ部分の色とつまみの位置で状態を示します。通知音のトグルとは別の見た目です。
- 画面は `dist/app.js` を配信するため、この動作の反映には `npm run build` と、API追加のためIDEサーバー（`server.mjs`）の再起動が必要です。

アクアリウムの状態は `ナビ水槽.js` が保持します。魚はポインターの近くでは餌への追従より回避を優先し、クリック時はクリックの縦位置にかかわらず、その横位置の水面から餌を落とします。餌は食べられたとき・水底到達時・18秒経過時に除去し、連打時も64粒を上限にします。一粒を食べた魚は個体ごとに15秒間、餌を追わず食べず、通常遊泳とポインター回避を続けます。待機期限は単調増加時計の実時間で保持するため、動きを減らす設定・非表示・別Documentへの移動でも延長しません。ホバー位置からは0.35〜0.75秒間隔で小さな気泡が上昇し、静止中も続きます。move連打では発生間隔を変えず、次の気泡を最新位置から出します。離脱後は新規発生を止め、既存の泡は水面到達または描画時間8秒で消えます。追加気泡は32個までとし、既存の背景の泡は維持します。気泡の動きは既存RAFと動きを減らす設定に従い、非表示中は停止、終了時に全て破棄します。水面の波紋はホバー中の位置を優先し、移動時は0.12秒以上の間隔で最新位置へ追従します。ポインターが離れると自動ランダム波紋へ戻し、Spaceのランダム追加も維持します。共通のpointer入力は要素の現在の表示範囲から比率へ変換し、leave・cancel・blur・別窓移動時に解除します。

万華鏡は `ナビ万華鏡.js` が描画し、ポインターに近い模様ほど形・色・線幅を強く変化させます。回転後の画面座標で距離を計算し、反対側の鏡像まで同じ強さで変化させません。既存の描画時計を共用し、動きを減らす設定にも従います。

`ナビ入力.js` はDOMの現在の `ownerDocument` にキーを登録し、別窓化・復帰で購読先を切り替えます。realmが異なるため `instanceof Element` は使いません。input、textarea、select、contenteditable（空属性／plaintext-onlyを含む）、標準ボタン等とIME入力を奪わず、blur／移動時に押下状態を解除します。破棄時はキー購読・移動検知タイマー・描画を解除します。
