# 2026-11-11

> CPU / eyes の採取方式を段階的に見直し、IDE の配置保存・読込、Avatar 起動、Windows ランチャー登録、Diag の待機負荷を調整。

## 主な変更

- CPU 取得は Windows ネイティブ採取、PowerShell プロセス再利用、固定周期・連続カウンター共有を経て、当日最後の `9789b9e` で `systeminformation.currentLoad` を CPU / eyes に採用。途中の採取方式を最終仕様として混在させない。
- `systeminformation-cpu.cjs` に、結果の有効範囲検査、要求タイムアウト、古い結果の破棄、休止後の初回値破棄を実装。ライブラリの百分率を周期比やコア数で割り直さず採用する。
- Windows のローカライズされた 3D GPU カウンターへのフォールバックと、読み取り専用の採取比較スクリプトを追加。
- IDE の配置 Save / Load を追加し、Ld を左端、Sv を右端に配置。CPU の初期幅・位置を Diag に合わせて調整。
- Avatar 起動を共通コマンドへ統一し、IDE 起動で内部認証を使用。CPU の単独セットアップと Windows ユーザー PATH へのプロジェクトランチャー登録を修正。
- Diag の Console ポーリングと管理処理の起床回数を減らす変更、ミニアイコンの右端表示と起動演出中のスクロール停止を追加。
