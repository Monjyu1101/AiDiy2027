🔀 AIタスク・AIチーム — 実装詳細

要求を投げると、AI が分解し、依頼を配り、実行して、経験を残す。すべて backend_taskteam の単一サーバー（ポート 8093）が回します。

🧩 要求の AI 分解

要求を「準備開始」で仮登録すると、起動監視が AI を呼んで開始行・処理行・終了行の明細へ分解し本登録する。分解は 2 段構えで、第 1 段が対象プロジェクトを読んで内容を組み立て、第 2 段が既定形式の JSON を書き出す。

sub_init.py2 段構えTK+8桁 採番

🕸️ 自由なタスクフロー（DAG）

カンバンの固定列でも垂直の流れ作業でもなく、先行SEQ（カンマ区切りで複数指定可）による DAG。先行明細が全完了した明細を実行可能とし、依存を満たしたものから並行起動する。フロー図は最長経路をクリティカルパスとして配置。

先行SEQ並行分岐クリティカルパス

⏱️ 実行開始条件

実行区分（即時 / 時間指定 / 間隔実行 / 定時実行）と実行条件（無し / フォルダ変化）の 2 軸。条件待ちは「準備完了」で待機し、成立したら明細 → 要求の順に「待機」へ戻して再実行する。停止中に過ぎた期限は一括発火せず次の周期へ送る。

Aタスク実行条件毎分ゲートフォルダ変化検知

✅ 自己検証つき実行

開始明細は AI を使わず aidiy_backup で差分バックアップを取る。処理明細は 1 ステップだけを Code AI へ依頼し、操作検証ありなら AI 自身の報告を確認して、書き込みなし・エラーなら最大 2 回まで自動リトライ。終了明細が最終検証を行う。

差分バックアップ操作検証自動リトライ

👥 AIチーム要員と依頼

依頼を登録すると、有効要員と各要員の蓄積経験（経験値・分類・直近の学び）を材料に AI が担当を選ぶ。経験のある要員へ寄せることで、貯めたナレッジがそのまま再利用される。担当が決まると AIタスク要求へ引き渡される。

persona 115 体TR+8桁経験ベース選定

🔁 作業ループ（PlanDo / SPDCA）

チーム目標に対して PlanDo（P 計画 → D 実行）または SPDCA（S 相談 → P 計画 → D 実行 → C 評価 → A 改善）を回す。ソース変更を許すのは D だけで、C と A は読み取り・テスト・動作確認に徹する。ループ回数は 1〜99（99 は無制限）。

PlanDoSPDCAD のみ変更可

💬 自動会話と取りまとめ

自動作業設定がオンなら、分の下一桁 1〜9 の回に雑談エリアの要員が 1 名ずつ「今やるべきこと」を発言する。発言はプロジェクトのソースを実際に読む調査モードで行う。下一桁 0 の回に、有効要員の 50% 以上の意見が集まっていれば admin 人格がチーム作業へ取りまとめる。

調査モード50% ゲートadmin 取りまとめ

🧠 経験の蓄積

依頼が完了すると、実行済み明細を AI が読み直して経験値・分類・まとめ・学びを生成し、Aチーム経験へ本登録する。次の依頼の担当選定がこの経験を参照するため、チームは回すほど適材適所になっていく。

Navigator で次の作業を考え、Console・Code・Live・IDE・Task・Team・Browser で進める。8 つの独立アプリが開発の各場面を支えます。

🧭 Navigator — 次の一歩を考える

開発目標と作業項目、推定達成率、次に AI へ渡すプロンプト案を確認する読み取り専用の案内画面。「ナビ」で作業項目を提案し、「評価」で達成度と次の提案を更新します。提案を自動実行せず、人が確認して次の作業を選びます。

aidiy_navi単独 / IDE から起動読み取り専用

aidiy_teamAI チームPlan / Do / Check

🎮 Discord — テキストも、声も

💼 Slack — スレッドで依頼を進める

専用チャンネルの投稿を HTTPS で定期取得し、aidiy_hermes の回答をスレッドに返します。スレッド内の返信は同じ会話として続きます。WebSocket を使わず外向き HTTPS だけで送受信し、プロキシ設定にも対応します（Slack API への通信許可と Bot 権限が必要です）。パネルは Discord 版と双子の構成で、Slack 版はテキスト会話に対応します。
