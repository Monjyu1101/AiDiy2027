10. セキュリティと本番環境

セキュリティの概要

このシステムは学習・開発用です。
本番環境で使用する場合は、以下のセキュリティ対策が必要です。

重要

開発環境のまま本番公開しないでください。
セキュリティ上の重大なリスクがあります。

開発環境 vs 本番環境

項目 開発環境 本番環境
JWT秘密鍵 your-secret-key-here ランダム生成した強力な鍵
パスワード 初期投入アカウントは平文、API作成の利用者はbcryptハッシュ（C利用者.パスワード） 全アカウントをbcryptでハッシュ化（初期投入分も再設定）
データベース SQLite（ファイル） SQLite（現行実装）
CORS localhost / 127.0.0.1 の 8090, 8092, 5173, 3000 とDocker用HTTP/HTTPSを許可 特定ドメインのみ
HTTPS HTTP（暗号化なし） HTTPS（SSL/TLS必須）
ログレベル DEBUG WARNING以上
Webサーバー Web 8090、Avatar 8092、5バックエンド 8091/8093/8095/8096/8098 Nginx（リバースプロキシ）

セキュリティチェックリスト

本番環境に移行する前に確認すべき項目です。

ステップ 1. 認証とアクセス制御
  • JWT秘密鍵をランダムな32文字以上に変更
  • トークン有効期限を短くする（推奨: 15分）
  • パスワードをハッシュ化する
  • 不要なエンドポイントを無効化する
ステップ 2. データベースの強化
  • パスワードをbcryptでハッシュ化
  • SQLiteファイルの配置先・権限・バックアップ運用を固定する
  • 外部RDBへ移行する場合は実装差分の洗い出しを行う
  • 定期バックアップを設定
ステップ 3. ネットワークセキュリティ
  • HTTPSを有効化（Let's Encrypt推奨）
  • CORSを特定ドメインに制限
  • ファイアウォールを設定
  • DDoS対策（Cloudflare等のCDN利用）
ステップ 4. ログと監視
  • ログレベルをWARNING以上に設定
  • エラー通知を設定
  • アクセスログを記録
  • 定期的なログ確認の仕組みを構築
ステップ 5. 運用体制
  • バックアップの自動化
  • 障害時の復旧手順を文書化
  • セキュリティアップデートの定期適用
  • アクセス権限の定期見直し

環境変数管理

秘密鍵や接続情報の管理方法です。

開発環境での設定

# backend_server/database.py
SECRET_KEY = "your-secret-key-here" # 開発環境ではOK
DATABASE_URL = "sqlite:///_data/AiDiy/database.db"

本番環境での設定

# .env ファイル（Gitに含めない）
SECRET_KEY=ランダム生成した強力な秘密鍵
DATABASE_URL=sqlite:///_data/AiDiy/database.db

# database.py
import os
from dotenv import load_dotenv

load_dotenv()
SECRET_KEY = os.getenv("SECRET_KEY")
DATABASE_URL = os.getenv("DATABASE_URL")
重要

現行リポジトリの実装はSQLite前提です。
本番運用時はバックアップ、排他制御、配置先、同時アクセス量を事前に評価してください。外部RDB化は追加実装が必要です。 

# .envファイルをGitから除外する
echo ".env" >> .gitignore

本番構成

JWT秘密鍵の生成

# ランダムな秘密鍵を生成
python -c "import secrets; print(secrets.token_urlsafe(32))"

Nginx設定

# /etc/nginx/sites-available/aidiy
server {
 listen 80;
 server_name yourdomain.com;

 # フロントエンド
 location / {
 proxy_pass http://127.0.0.1:8090;
 proxy_set_header Host $host;
 proxy_set_header X-Real-IP $remote_addr;
 }

 # Core API
 location /core/ {
 proxy_pass http://127.0.0.1:8091/core/;
 proxy_set_header Host $host;
 proxy_set_header X-Real-IP $remote_addr;
 }

 # Apps API
 location /apps/ {
 proxy_pass http://127.0.0.1:8098/apps/;
 proxy_set_header Host $host;
 proxy_set_header X-Real-IP $remote_addr;
 }
}

Systemdサービス

Core APIとApps APIの2つのサービスを登録します。

# /etc/systemd/system/aidiy-core.service
[Unit]
Description=AiDiy2027 Core API
After=network.target

[Service]
User=aidiyuser
WorkingDirectory=/var/www/AiDiy2027/backend_server
Environment="PATH=/var/www/AiDiy2027/backend_server/.venv/bin"
ExecStart=/var/www/AiDiy2027/backend_server/.venv/bin/uvicorn core_main:app --host 0.0.0.0 --port 8091

[Install]
WantedBy=multi-user.target
# /etc/systemd/system/aidiy-apps.service
[Unit]
Description=AiDiy2027 Apps API
After=network.target

[Service]
User=aidiyuser
WorkingDirectory=/var/www/AiDiy2027/backend_server
Environment="PATH=/var/www/AiDiy2027/backend_server/.venv/bin"
ExecStart=/var/www/AiDiy2027/backend_server/.venv/bin/uvicorn apps_main:app --host 0.0.0.0 --port 8098

[Install]
WantedBy=multi-user.target

デプロイ手順

  1. サーバー準備 — Ubuntu/CentOS等のLinuxサーバーを用意
  2. 必要ソフトウェアのインストール — Python, Nginxをインストール
  3. コードのデプロイ — Git clone または SCP/FTPで転送
  4. 環境変数の設定 — .envファイルを作成
  5. 依存パッケージのインストール — uv sync
  6. データベースの初期化 — SQLiteファイル配置と初期データ投入を確認
  7. サービスの起動 — systemctl start aidiy-core および systemctl start aidiy-apps
  8. Nginx設定 — リバースプロキシとHTTPS設定
  9. 動作確認 — ブラウザからアクセスして確認
Tip

デプロイ手順をスクリプト化しておくと、再デプロイ時に便利です。

Docker対応

現行リポジトリには docker/ の実装済み構成があります。Core / Apps / frontend_webを1つのアプリコンテナで動かし、別のNginxコンテナがHTTPSと静的配信を担当します。

cd docker
docker_1build.bat  # 初回またはWeb変更反映時
docker_2start.bat  # 起動
docker_3stop.bat   # 停止
  • 画面: https://localhost/（自己署名証明書）
  • ホスト公開ポート: 80, 443, 8091, 8098。Webの8090はコンテナ内部のみ
  • frontend_webは docker/Dockerfile の frontend-builder ステージでビルドし、named volume経由でNginxへ共有する。ホストの frontend_web/dist/ は使わない
  • backend_tools (8095)、backend_taskteam (8093)、backend_local (8096) はこのDocker構成に含まれない
  • Nginxに /task / /team proxyはないため、AIタスク画面とAIチーム画面はこの構成では動作しない
  • 詳細と証明書・削除手順は docker/README.md を一次情報とする
注意

_config/ はread-onlyでマウントされます。秘密情報をイメージやComposeへ直書きせず、ホスト側の設定を管理してください。

監視とロギング

本番環境での監視項目です。

  • 死活監視 — uptimeチェック（UptimeRobot等）
  • エラー監視 — エラートラッキング（Sentry、Rollbar等）
  • リソース監視 — CPU/メモリ使用率の監視
  • アクセスログ — 不正アクセスの検知
  • バックアップ監視 — DBバックアップの成功確認
