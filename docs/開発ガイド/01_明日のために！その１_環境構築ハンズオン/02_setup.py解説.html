02_setup.py解説

対象ファイルは workspace/AiDiy2027/_setup.py です。このページでは、何を準備し、何をスキップするかを整理します。

コード全体（参照）

次のコードブロックは、理解しやすいよう core/apps・Web・Avatarのセットアップだけに絞った簡略版（code_samples/_setup.py）を読み込んで表示しています。
実際のルート _setup.py はこれに加えて、バックエンド(tools/local/task,team)と command_hermes のセットアップも行います（対象は8項目）。処理の考え方（対話形式で項目ごとに実行可否を確認する）は共通です。

主な定数

定数内容影響
BACKEND_PATHbackend_serverバックエンド作業ディレクトリ
FRONTEND_PATHfrontend_webフロントエンド作業ディレクトリ
DATABASE_TYPEsqlitePostgreSQL 関連処理をスキップする分岐条件
AUTO_MODE対話質問の自動回答フラグ開始時に a を選ぶと有効

処理順序

  1. 開始確認（y / n / a=auto）
  2. グローバルツール更新（pip, wheel, setuptools, uv）
  3. グローバル npm ツール更新（AI CLI群）
  4. バックエンド環境準備（uv sync）
  5. フロントエンド環境準備（npm install + npm update）
  6. DATABASE_TYPE が postgresql の場合のみ DB 復元とマイグレーション
  7. 完了メッセージ表示

重要ポイント1: 依存関係の準備

バックエンド

  • check_uv_installed() で uv の存在確認
  • check_python_venv() で既存仮想環境確認
  • uv sync で Python 依存関係を同期

フロントエンド

  • check_npm_installed() で npm の存在確認
  • package.json の存在確認
  • npm install で依存関係を取得
  • npm update で package.json の宣言範囲内の最新版へ更新

重要ポイント2: SQLite運用時の挙動

本プロジェクトの既定値は DATABASE_TYPE="sqlite" です。したがって、以下は通常スキップされます。

  • PostgreSQL ユーザー作成確認
  • 初期 SQL 復元
  • alembic upgrade head

SQLite ファイルの実体は workspace/AiDiy2027/_data/AiDiy/database.db です。

重要ポイント3: 対話形式と失敗時の継続

設計説明
質問ベース各ステップで実行可否を確認して進む
続行確認失敗時に「続行するか」を確認する箇所がある
AUTOモードデフォルト回答で進めるため、繰り返し検証時に便利

実行例

cd workspace/AiDiy2027
python _setup.py

# 対話に従って必要な処理を実行
# 完了後は以下で起動
python _start.py

チェックリスト

  • uv sync が成功している
  • npm install と npm update が成功している
  • python _start.py に進める状態になっている
