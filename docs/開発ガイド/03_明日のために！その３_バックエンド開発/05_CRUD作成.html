  • 認証情報がない場合は system を利用（初期化時など）

論理削除パターン（T系を中心に使用）

物理削除（db.delete()）ではなく 有効 = False に設定する論理削除を使います。T系では特に重要です。

def delete_T配車(db: Session, 配車伝票ID: str, 認証情報=None):
    """T配車を論理削除（有効フラグをFalseに設定）"""
    db_item = get_T配車(db, 配車伝票ID)
    if not db_item:
        return False
    audit = update_audit_fields(認証情報)
    db_item.有効 = False  # 物理削除ではなく論理削除
    for key, value in audit.items():
        setattr(db_item, key, value)
    db.commit()
    return True

ポイント:

  • CRUD関数内で論理削除する場合は update_audit_fields（更新系4項目のみ）を使う
  • Router側で論理削除する場合は create_audit_fields(認証情報, is_update=True) を使う（どちらも同じ動作）
  • 論理削除後も get_ 関数では取得できてしまうため、一覧取得時の list_controls.py による有効フィルタが重要

設計ポイント

  • CRUDは例外時に呼び出し元で rollback できるようにする
  • 戻り値はRouterでそのままレスポンス化できる形式にする
  • 重複チェックや存在チェックはRouterで行う（必要時のみ補助関数へ切り出す）
  • 削除はCRUD関数またはRouter内で論理削除（有効 = False）を実装する

【重要】apps_crud/__init__.py への登録を忘れずに

新規CRUD作成後は必ず apps_crud/__init__.py への登録が必要です。

  • CRUDファイル（例: apps_crud/M仕入先.py）を作成しただけでは不十分
  • apps_crud/__init__.py に以下を追加する必要があります:
    • import 文: from apps_crud.M仕入先 import get_M仕入先, get_M仕入先一覧, create_M仕入先
    • __all__ リスト: 'get_M仕入先', 'get_M仕入先一覧', 'create_M仕入先'
  • 忘れると Router で crud.get_M仕入先 が使えず、ImportErrorやAttributeErrorが発生します
  • 過去実績: M仕入先追加時にこの登録漏れでエラーが発生しました

チェック

  • [ ] CRUD関数名とRouter呼び出し名が一致する
  • [ ] 監査項目の設定漏れがない
  • [ ] コミット/リフレッシュ処理が適切に配置されている
  • [ ] 【重要】apps_crud/__init__.py にimportと__all__追加済み
  • [ ] 削除関数は物理削除（db.delete()）ではなく論理削除（有効 = False）になっている
